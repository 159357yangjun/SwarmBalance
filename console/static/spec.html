第 0 章总则与设计哲学

核心命题。仿真软件 ≠ 看起来像的视频。仿真软件 = 维护一套独立的世界状态，内核驱动状态变化，渲染仅把状态画出来。

P1 · 状态优先
世界状态是唯一真相，画面只是它的一种输出。
P2 · 渲染单向
渲染禁止反向修改世界状态，渲染结果禁止作为仿真逻辑输入。
P3 · 确定性
相同初始条件 + 相同种子 → 每次运行逐拍一致。

四层职责：仿真内核（纯逻辑）→ 场景管理（状态容器/快照）→ 渲染（只读视图）→ 交互（改状态而非改像素）。

第 1 章世界逻辑规范（WL）

WL-1 时空基准

WL-1.1
必须采用本地投影米制平面坐标（OSM 导出），单位米。
WL-1.2
必须以离散步推进，且 1 step = 1 秒（STEP_SECONDS = 1.0）；该映射必须在代码常量与 UI 显式声明。
WL-1.3
单局 episode_max_steps = 3600 → 1 小时仿真。
WL-1.4
禁止混用单位；全系统统一 m / s / kg / Wh。

WL-2 实体规范

WL-2.1 无人机（真实机型锚定）

无人机必须以真实公开机型参数建模，禁止使用无来源的魔法数。

类型参考机型速度 m/s载重 kg电池 Wh能耗 Wh/m满载航程 km
light_express 轻载快递美团第四代配送无人机20.02.4380.00.03210
standard_cargo 标准货运顺丰丰翼方舟 ARK4014.010.01600.00.0620
heavy_cargo 重载运输大疆 FlyCart 30 双电20.030.03968.80.14216
WL-2.1.1
运动学：每步沿航线航点直线位移 speed × STEP_SECONDS 米。
WL-2.1.2
能耗 = 距离 × 基础能耗 × (1 + 载重比 × 载重惩罚系数)；到点即扣电。
WL-2.1.3
低电必须触发预判式改道换电；任务链放行必须保留电量储备（默认 15%）。

WL-2.2 机巢（换电站）

WL-2.2.1
默认 5 站，换电 180 s，泊位有限（默认 2）。
WL-2.2.2
泊位竞争必须用动态优先级仲裁（电量 / 等待 / 任务紧迫度），并提供 FIFO 对照。
WL-2.2.3
禁止关闭最后一个可用机巢。

WL-2.3 任务 / 需求

WL-2.3.1
每个任务必须携带：重量、取货点、送达点、生成时刻、优先级(1–3)、类别(urgent/emergency/bulk/normal)、截止时刻、状态。
WL-2.3.2
截止时刻必须基于可解释 SLA：deadline = 生成时刻 + random(900,3600)s，参考速度 14 m/s、基础 420 s、每 kg +24 s。

WL-2.4 禁飞区

WL-2.4.1
禁飞区为飞行硬约束，必须参与路径规划；穿越必须触发绕飞并计数。
WL-2.4.2
任务起点/终点落在禁飞区内必须被拒绝。

WL-3 单步推进规范

step(actions) 每次调用必须依次完成：

  • 将 {drone_idx: [task_id,...]} 分配为航线；支持同源追加与异源"顺路接入"任务链（上限 3 段、绕飞阈值 1500 m）。
  • current_time += 1（秒）。
  • 按需生成新任务（交互式控制台可暂停自动订单流）。
  • 各无人机 update()：沿航点运动、扣电、到点取/送货、低电改道换电。
  • 统计：里程（区分空载/载货）、能耗、利用率、任务完成（航点弹出判定）。
  • 返回 observation / reward / done / info。

WL-4 需求生成规范禁止均匀乱撒

WL-4.1
取送点必须以热点聚类生成：默认 60% 概率落在热点中心（医院/商圈）半径 80 m 内。
WL-4.2
到达必须呈高峰/平峰潮汐：peak 20 步/单、平峰 45 步/单，peak 概率 0.7，周期 1200 步。
WL-4.3
重量必须按分档抽样，且对应真实物流品类（见下表）。
重量区间概率对应品类对标机型
1–2 kg55%外卖 / 小件包裹美团轻载
3–10 kg35%标准快递包裹顺丰 ARK40
11–25 kg10%重货 / 应急物资大疆 FlyCart 30
WL-4.4
单局默认 60 单、初始 12 单。

WL-5 环境与约束

WL-5.1
建筑/路网必须来自真实 OSM 数据（当前杨浦区局部）。
WL-5.2
场景应当支持环境事件（插单、改优先级、故障停飞、关闭机巢；风场/天气为规划项）。

WL-6 指标口径

WL-6.1
必须至少统计：完成率、准时率、加权延迟、生成→送达时长、超时率、总能耗(Wh)、空载/载货里程、机队利用率、顺路接入、禁飞绕飞、泊位利用率、排队等待。
WL-6.2
所有指标必须机械可复算（同一快照 → 同一指标值）。

第 2 章软件架构规范（SA）

SA-1 分层

系统必须分为五层，依赖只能自上而下；禁止仿真内核 import 任何渲染库或 Web 框架。

Layer 5 · UI / 交互层
命令：insertTask / setPriority / killNest / pauseOrders → 改世界状态
Layer 4 · 渲染层（只读，双实现）
Web three.js ／ 桌面 pygame —— 消费同一份世界状态
Layer 3 · 仿真时钟
固定步长时钟；服务端固定推进 + 客户端插值
Layer 2 · 场景管理 / 世界状态
WorldState · 注册表 CRUD · 快照/检查点/回放
Layer 1 · 仿真内核（纯逻辑）
运动学 / 需求 / 仲裁 / 规划 / 避障 / 随机源
Layer 0 · 领域实体
DroneState / TaskState / NestState / NoFlyZoneState

SA-2 仿真内核（Simulation Core）

SA-2.1
必须为纯逻辑：无 UI、无渲染、无网络，可在无显示环境直接运行。
SA-2.2
必须可独立单元测试（不启动窗口、不依赖图形库）。
SA-2.3
输入初始参数 + 逐步 actions，输出每一时刻世界状态。

SA-3 场景管理 / 世界状态（Scene Manager）

SA-3.1
必须有单一 WorldState 容器：全部实体 + 仿真时钟 + 随机源状态 + 指标。
SA-3.2
必须提供实体注册表增删查（按 id）。
SA-3.3
必须提供整世界状态序列化/反序列化（快照）与 hash_state()。
SA-3.4
必须提供检查点保存/恢复与步历史（回放）。

SA-4 仿真时钟（Simulation Clock）

SA-4.1
必须采用固定时间步，物理步长与渲染帧率解耦。
SA-4.2
服务端应以固定速率时钟推进内核；客户端应在相邻两次快照间插值渲染（画面卡时物理不变慢）。
SA-4.3
禁止把物理计算放在渲染循环内。

SA-5 渲染层契约

SA-5.1
渲染必须只读：从世界状态/快照构建视图，禁止回写状态。
SA-5.2
可见性是渲染属性，不是存在属性：被遮挡/不可见禁止导致实体从场景中删除。
SA-5.3
禁止依赖渲染结果（裁剪、遮挡、透明度）做仿真判定。
SA-5.4
允许 Web 与桌面双实现，二者必须消费同一份世界状态。

SA-6 交互层契约

SA-6.1
所有交互必须通过命令修改世界状态，禁止直接改渲染画面。
SA-6.2
非法命令必须被拒绝且整体回滚，世界状态保持不变。

第 3 章仿真工程准则（SE）

SE-1 时间步长

SE-1.1
采用固定时间步（推荐）；禁止跟随帧率的可变步长。
SE-1.2
仿真逻辑与渲染逻辑必须分离，运行于不同循环/线程。

SE-2 状态与对象管理

SE-2.1
每个物体必须有独立状态存储（id、位置、速度、质量 + 业务标签）。
SE-2.2
属性必须分类：物理（位置/速度/质量）、渲染（颜色/可见性/纹理）、业务（id/标签）。
SE-2.3
物体销毁必须显式调用；禁止以"关掉渲染"等同于"消失"。

SE-3 渲染层陷阱

SE-3.1
渲染画面禁止反向影响世界状态。
SE-3.2
遮挡必须用业务层标记或射线查询实现；射线只查询，不改变世界。

SE-4 确定性

SE-4.1
所有随机必须走集中式、可种子化的随机源。
SE-4.2
核心仿真必须单线程；禁止让线程调度不确定性破坏确定性。
SE-4.3
必须支持保存整场景快照并加载回到过去某一刻；快照只保存世界状态，不保存画面。

SE-5 数值稳定与边界

SE-5.1
位置必须有边界守卫（越界 clamp 并标记）；必须有 NaN/数值爆炸兜底。
SE-5.2
应当有"卡死/无进展"检测（连续 N 步未移动且无任务 → 标记，不静默）。

SE-6 单位

SE-6.1
全系统统一单位，见 WL-1.4。

SE-7 序列化与回放

SE-7.1
必须支持场景保存/加载；浮点序列化注意精度。
SE-7.2
回放可用两种方式：实时重仿真 或 状态序列回放（当前实现为后者）。

SE-8 测试

SE-8.1
禁止仅靠肉眼判断仿真对错；必须有自动化测试直接读内核数据做断言。
SE-8.2
必须覆盖：确定性（同种子逐拍一致、快照往返一致）、遮挡不变量、越界守卫、非法命令回滚。
SE-8.3
单元测试禁止依赖渲染。

SE-9 依赖与物理引擎选型

SE-9.1
明确决策：不引入 PyBullet / Bullet3 / ODE 等刚体物理引擎。本项目是运动学调度-优化仿真（航线预规划 + 规划期绕障），非刚体动力学；引引擎只增依赖与不确定性而无法建模真实问题。
SE-9.2
若未来需风场扰动/悬停-巡航能耗差，应在核内用确定性解析公式实现，仍不上引擎。

附录 A术语

  • 世界状态（World State）：一切仿真对象的当前数值集合，渲染的唯一输入。
  • 快照（Snapshot）：世界状态在某一时刻的完整序列化。
  • 固定时间步（Fixed Timestep）：以恒定步长推进仿真，与渲染帧率无关。
  • CCD（连续碰撞检测）：避免高速物体隧穿的检测方式（本项目因运动学建模暂不需要）。
  • SLA：服务等级（此处为送达时限基线）。
