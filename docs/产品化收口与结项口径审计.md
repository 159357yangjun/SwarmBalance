# SwarmBalance v0.8：产品化收口与结项口径审计

本文用于项目结项前的**代码收口、答辩口径统一和风险检查**。原则是：申请书承诺的核心能力必须能在代码、实验和演示中找到对应实现；实现阶段增加的功能可以保留，但不要把扩展能力反过来改写成申请书原本的研究主线。

## 1. 结项主线

建议最终统一表述为：

> 群智优衡是一个面向城市应急与低空物流场景的异构无人机集群三维协同调度仿真平台。系统围绕“异构能力匹配—任务链时序优化—机巢有限资源动态调度”三条主线，在统一仿真环境中支持任务生成、滚动调度、三维可视化、运行时事件注入与多算法实验评测。

算法定位固定为：

- **GA：主推优化算法**，排列编码 + 约束感知贪婪分割 + 能力匹配 + 解码后局部搜索；
- **Greedy：启发式基线**；
- **OR-Tools：经典求解器基线**；
- **PSO：群智能扩展对比**；
- **IQL / VDN / QMIX：MARL 扩展对比**，不替代申请书主线。

## 3. v0.8 产品化收口

### 3.1 场景库与运行态快照分工

新增持久化“场景库”：

- 保存完整 `simulation.json`；
- 保存推荐算法和 Seed；
- 可选保存 `backend_si/config.yaml` 算法超参；
- 支持 JSON 导入、导出、删除和一键应用；
- 场景应用失败自动回滚原配置；
- 导入文件有 2 MiB 上限，场景 ID 不直接使用用户输入，避免路径穿越。

**场景库 = 可复现初始条件。** 适合答辩场景、实验场景和跨机器分享。

**运行态快照 = 当前服务内某个动态节点。** 适合“故障前 / 插单前 / 拥堵时”回放。结构性重建会使旧快照失效，这是有意设计。

### 3.2 启动预检

`python -m console.run` 现在启动前检查：

- Python 是否为 3.10；
- `numpy / osmnx / shapely / networkx / PyYAML / FastAPI / uvicorn / OR-Tools` 等关键依赖；
- 异构机型数量之和是否等于 `num_drones`；
- 是否存在至少一个机巢、机巢 ID 是否重复；
- SLA 上下限、任务生成数量、数据源类型等基础配置。

Windows 可直接双击 `start_console.bat`。预检通过后本地服务自动打开浏览器；预检失败时给出可操作的中文错误，不再直接暴露长 traceback。

### 3.3 Web 信息架构

- “指标”统一为“态势”；
- 新增“当前算法 / 任务压力 / 机队资源 / 地面资源”四项摘要；
- 根据 P3 积压、低电、停飞、关闭机巢、泊位排队自动生成操作建议；
- 首次打开显示推荐操作流程；
- Web 配置保存失败时保留配置窗口并显示原因，不再静默关闭。

## 4. 本轮代码审计已修复问题

### A. 回合步数热重建未真正生效

旧版 `SimSession` 在创建时把 `episode_max_steps` 固化，Web 后续修改 `simulation.json` 再 `rebuild()` 时仍可能沿用旧值。

v0.8 在每次 `rebuild()` 时重新读取 `environment.episode_max_steps`，保证界面配置和实际 Environment 一致。

### B. 配置保存缺少统一校验

旧版 Web 可以把“10 架无人机 + 机型配比总和 8”这类不一致参数写回文件，错误往往直到重建/运行阶段才出现。

v0.8 新增 `console/config_validation.py`，启动预检、Web 配置保存和场景导入共用同一套轻量校验。

### C. 场景导入的安全与回滚

v0.8 场景库：

- 文件名使用内部随机 ID，不信任导入文件中的路径；
- 限制导入大小；
- 应用失败同时回滚 `simulation.json` 和算法配置；
- 答辩预设临时配置尚未恢复时禁止叠加场景库，避免配置层次混乱。

### D. 预留 TODO 的收口

`FitnessEvaluator` 中电池使用率和负载均衡两个预留方法已实现通用归一化逻辑。默认权重仍不启用二者，因此不会偷偷改变既有实验结果。

### E. 项目元信息

`CITATION.cff` 在 v0.8 已改为实际 Gitee 仓库地址；当前发布元信息已随 v1.0 更新。

## 5. 必须坚持的答辩边界

以下说法**不要使用**：

1. **“GA 保证全局最优 / 实现数学意义上的总耗时最短”**。GA、局部搜索和启发式方法只能说以相应目标优化并通过实验比较效果；OR-Tools 也受降维模型和求解时限约束。
2. **“已经实现真实无人机飞控容错/故障诊断”**。当前故障是调度层场景事件注入，用于研究任务回收和资源变化后的重调度。
3. **“Web 已实现 WebSocket / SSE 实时推送”**。当前控制台使用 REST 轮询和批量步进刷新，用户体验上可以实时观察，但技术实现不是 WebSocket/SSE。
4. **“这是已经可直接商用部署的真实低空交通系统”**。当前是纯软件仿真研究平台，地图、能耗、任务和故障模型均有抽象。
5. **“PSO / MARL 是申请书核心创新”**。它们是实现阶段扩展；主线仍是 GA + 能力匹配 + 任务链 + 机巢动态调度。
6. **“候选无人机解释排名就是 GA 的决策结果”**。候选排名属于解释层，最终任务分配必须以当前 Scheduler 真正执行后的任务链为准。

更稳妥的表述是：

> 系统在统一约束仿真环境中实现可解释的滚动调度与资源竞争模拟，并通过多场景、多随机种子实验量化比较不同策略的完成时间、超时率、利用率、空载率和机巢周转表现。

## 6. 当前仍需在正式环境完成的验证

当前代码级检查不能替代真实地图联调。正式提交前建议在 **Python 3.10 + 完整 requirements** 环境执行：

```bash
python -m console.run
python run_conclusion.py --preset quick
python run_conclusion.py --preset conclusion
```

至少人工走一遍：

1. 2D / 3D 地图加载；
2. GA 正常播放与单步；
3. 人工插入 P3 任务并重调度；
4. 机巢排队；
5. 无人机故障后任务回收；
6. 场景保存 → 导出 → 删除 → 重新导入 → 应用；
7. 运行态快照保存/恢复；
8. quick 实验完整输出 CSV / 图表。

## 7. 已知但暂不阻塞结项的工程风险

- Web 前端 Vue / ECharts / Three.js **已本地化**到 `console/static/vendor/`（三库随仓库分发，页面优先从 `/vendor/*` 加载，仅在失败时回退 CDN 并在完全不可用时显示诊断卡）。断网首开不再是风险。原建议「正式答辩电脑提前打开一次并确认浏览器缓存，或后续把三份前端库 vendoring 到 `console/static/vendor/` 后改成本地加载。
- MARL 训练链路依赖其独立环境与训练成本，不建议在答辩现场训练；展示已有结果或作为扩展架构说明更稳定。
- OSM/城市模型仍属于仿真地图，不能把避障结果表述为真实空域审批或真实飞行安全认证。

## 8. 结项演示推荐顺序

1. `start_console.bat` 启动，展示预检通过；
2. 从“场景库”加载固定答辩场景；
3. 进入“态势”看系统健康、任务压力与资源状态；
4. GA 播放数步并暂停；
5. 插入 P3 急救任务 → 查看候选解释 → 单步触发真实重调度；
6. 查看无人机任务链和机巢动态优先级队列；
7. 保存运行态快照，制造无人机故障，再观察任务回收和重新分配；
8. 恢复快照，说明系统可复现；
9. 进入“实验”页展示一键标准实验和敏感性分析结果。

这套顺序同时覆盖“系统能操作”“算法有主线”“约束有体现”“实验可验证”四个结项关注点。


## v0.9 补充：便携运行不是正式实验环境

v0.9 新增内置离线 OSM XML 回退和 `--portable` 启动模式，用于答辩机依赖异常时保证 Web 演示可启动。该模式不会伪装成完整环境：页面显示“离线便携”，OR-Tools 缺失时直接禁用，复杂 OSM multipolygon relation 仍交给 OSMnx 完整模式。**论文与结项对比数据仍应在 Python 3.10 + OSMnx + OR-Tools 的正式环境生成。**

发布前推荐运行 `python release_check.py --strict`；应急演示可使用 `start_console_portable.bat`。详见 `离线便携与端到端自检.md`。

## v1.0 补充：实验结果证据链冻结

v1.0 不再用“只看均值”的方式作为结项证据。`ExperimentRunner` 在同一批 Seed 上保留每次原始运行，并额外生成：

- `algorithm_comparison_stats.csv`：均值、总体标准差、中位数；
- `paired_ga_vs_greedy.csv`：GA 与 Greedy 的同 Seed 描述性配对比较；
- `reproducibility.json`：运行环境、依赖版本、输入文件哈希；
- `summary.md`：自动写入结果解释边界。

这里的“配对比较”**不是统计显著性检验**。若结项实验结果与预期不一致，报告应如实解释场景、约束或参数原因，不能为了申请书措辞而筛掉不利 Seed、改指标定义或选择性展示结果。

正式交付可运行 `finalize_project.bat`，它只在 `release_check.py --strict` 通过后继续执行标准 `conclusion` 实验并构建结项证据包。便携模式仍只用于演示兜底，不能替代正式实验环境。
