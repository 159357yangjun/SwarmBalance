## A. 三层证据，不能混称完成

| 层级 | 已有证据 | 不得推导的结论 |
|---|---|---|
| L1 软件守恒及故障安全 | B4e→B5g 独立 RED→GREEN、9-job、固定 HEAD、严格 scope | 不等于任务队列全部在一个 SQLite 原子事务中 |
| L2 仿真模型与调度结果 | 配对 seed/grid、能量路径不变量、E0/E1 结构化预设、结果复现清单 | 不等于绝对 Wh/km、风/载重的参数已用实测标定 |
| L3 真实无人机适用性 | 地图/部分厂家参数可核；其它实测数据来源登记在数据溯源文件 | 不等于真实航路、救援交接和飞行安全已获证实 |

**已知安全边界：**
- B5b/B5c 的外部交接属于操作员输入的**仿真确认**，不是独立的身份与实物验证。
- B5d 追加日志使用 SHA-256 链式摘要，可检出意外损坏，不是抗具备写权限攻击者的防篡改签名。
- B5e `prepared/committed` 是独立事务日志，不保证 `Environment` 的队列与文件系统原子更新。
- B5f/B5g SQLite 对账依赖调用方给定的**可信同一状态** `Environment`；B5g `BEGIN IMMEDIATE` 串行化合作的本地 SQLite 调用者，不能阻止绕过桥接接口的并发内存改写。
- 尚未实现完整 `Environment`（时间、无人机、航点、任务队列、机巢、随机数状态）的一致性 checkpoint/restore；不能写“系统断电后无条件安全恢复”。

## B. 本轮找到的可复现证据缺口

`experiments/reproducibility.py` 的 schema v2 清单以前只登记了 `SWARM_BALANCE_SIM_CONFIG`。
即使 B5a/B5b/B5c/B5f/B5g 或规划/风实验开关为 1，旧清单也可能**无法显示**差异；
启用 SQLite 货权实验时，`console/custody_journal.py`、
`console/custody_transaction.py` 和 `console/custody_queue_bridge.py`
还不在共用源码哈希证据中。

真实 RED：[Actions #38131843709](https://github.com/159357yangjun/SwarmBalance/actions/runs/38131843709)，
5 个审计测试，3 FAIL、2 PASS。三个失败分别为“开启标志未登记”“关闭默认未登记”“启用货权审计时源码哈希缺失”。
结构配对和冻结预设字节不变已经成功，不必伪装成同一类错误。

本审计修复原则：
1. **枚举已确认影响仿真的 11 个特性开关**，按实际环境值登记；没设置时写明 `0`，而非从全环境变量扫入隐私/密钥。
2. 只在 B5 货权功能实际开启时，纳入三个 `console/custody_*.py` 的 SHA-256。已有核心执行源和各算法源码哈希保持原样。
3. `schema_version=2`、原本清单的 `SWARM_BALANCE_SIM_CONFIG`、实验结果内容、算法代码、飞行公式与冻结 E0/E1 预设均不改变。
4. 对 B5g 历史四文件范围门固定已验收 SHA；为本审计额外添加**独立的五文件 scope gate**。历史测试不能因审计新增文件误判为 B5g 变更。

## C. 研究实验准入门（下一阶段，不代表已获得统计结果）

| 门 | 要先取得什么 | 强制失败条件 |
|---|---|---|
| R0 问题定义 | 一个固定区域、任务生成口径、机队/算法清单、时间窗口和指标定义 | 混用真实地图与合成订单却称为真实运营数据 |
| R1 能量量纲核验 | `Wh`、`km`、载重、风速单位；理论里程单点测试与实际执行账本一致 | 同条件预测和执行不一致、单位错置或“完成率全满”而不解释 |
| R2 真实参数准入 | 可下载的来源文件、许可、机型、采样频率、工况、质量标记、留出整次飞行 | 仅引用他机型的 `Wh/km` 绝对量级；拿不到数据却称标定完成 |
| R3 配对实验量具 | E0(C1,C2) 与 E1(calm/east6/west6) 的场景/seed/repeats 一致；结果另存，不覆盖冻结结果 | 缺轴/只改标签、seed 不匹配、静风不是零风 |
| R4 调度算法比较 | Greedy/GA/PSO/OR-Tools 同任务流、同能耗模型、同资源约束；分负载档给配对差分和 CI | 单个 seed 或不公平负载下声称算法最优；只报均值无分布与超时 |
| R5 敏感性/外部有效性 | 至少分开报告假设、厂家参数、公开飞行与合作实测四级来源 | 把静态单元测试或数字孪生模拟当飞行安全认证 |

**重要的历史告警：** `docs/无人机设备数据源与能耗标定方案.md`
曾记录早期评测能量消耗与厂家派生参考量级差异极大；
该结果有具体旧版输入与 CSV 依据，但**不能直接推广到目前 HEAD**。
进入 R1 时先对固定版本重新核算，不改公式来迎合目标数值。
旧文档同时记录 CMU KiltHub 下载受限、机型不同，需重新获取与核查才能升为可用真实标定数据。

## D. 下一轮可直接执行的顺序

1. 固定候选 HEAD、保留原始 E0/E1 和 `results/compare`；只做 **dry-run 计划与复现标识审计**。
2. 选同一任务流、同一能耗/风假设，测完整的能量账本，先判断能否进入 R1；不通过则停止发表调度收益结论。
3. 获取**可复核飞行数据**后按整次飞行留出集标定参数，公开绝对误差与区间；对不匹配机型明确限定推论。
4. 通过模型门后运行配对的调度算法对照与负载敏感性，报告完成率、超时率、延迟、Wh、换电、未完成任务与样本量。
5. 安全链若需要合并到 master，应另做集成清单、合并顺序、端到端恢复演练与发布评审；不得把单 PR CI 绿灯当集成完成。

**结论**：当前优先补“实验来源与量具可信度”的证据，而不是继续无限延伸 B5 功能编号。
