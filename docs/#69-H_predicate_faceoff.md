# #69-H 谓词候选对撞：几何"被越过" vs 后缀形状（数据裁决，未落码）

基线 9b1cd15。主控定标："消费事件的真伪证人应是 prev[0] 本步被越过（几何），不是 curr 形状；两例各归其位再定谓词"。本轮按此实现了几何谓词并跑两面 + seed40907 冻结回放，结果**推翻了"几何谓词一定更优"的假设**，故未替换已提交的规则，停在证据交裁。

## 一手数据

### 1. 几何谓词确实修掉了已提交规则的假阳性（你的担心成立）
seed102 全轨迹扫描：把"服务航点从队首消失"计为送达的旧规则，有 **9 例 mid-flight re-route 假阳性**——无人机停在离 dest/source **85~961 m** 处、根本没经过该点却被记消费：
```
t=436 drone0 dest dist_after=85.7 | t=1580 drone1 source 924.3 | t=1634 drone9 dest 961.2 …（共 9）
```
纯几何谓词（`dist(end, prev[0]) ≤ 1m` 才计）把这 9 例判回 k=0 ✅，task_44（end==dest 精确）判 k=1 ✅。单看这两面，几何谓词完胜。

### 2. 但几何谓词在 seed40907 上动了冻结证人（违反验收 (b)）

### 3. 根因：两规则**双向发散**，谁都不是谁的超集
seed40907 逐步对撞 geo_svc vs suffix_svc，11 处分歧，两个方向都有：
```
geo>suffix: t=79(source) 169(dest) 171 196 759 923   ← 几何多计
geo<suffix: t=521(dest) 572(source) 659(src×2) 724 778  ← 几何漏计
```
- **geo<suffix**（如 t=521）：一步内先弹掉一个普通 waypoint、再弹 dest，prev[0] 是 waypoint 不是 dest ⇒ 几何"从队首连续匹配"遇 waypoint 终点不等就停，漏掉更深的服务点。
- **geo>suffix**（如 t=79）：curr 恰好不是 prev 后缀（同帧追加）但无人机确实越过了 source ⇒ 几何计、后缀不计。

⇒ **纯几何和纯形状都是错的子集**。真正的证人要同时满足："prev[:k] 这批点在几何上都被本步位移扫过（含途经非服务点后到服务点）" 且 "curr 与剩余一致" —— 即需要沿 prev 累加判断每段是否落在 [start,end] 行进路径上，而非只比 end 与 prev[k]。这是一个**尚未设计正确**的谓词，我不为了压过某个夹具硬凑第三个猜测（遵你"别收窄到只认 task_44"）。
