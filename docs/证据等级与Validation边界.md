# 证据等级与 Validation 边界

> 生成方式：本文所有数字均为**本轮亲自重跑/重解析得到**，每条附复算命令。
> 取证时间：2026-10-06（本机 `.venv310` / Python，网络为 curl 直连 Zenodo API）。
> 本文只回答一个问题：**当前项目的数据可信到什么程度，以及"再往上抬一级"需要什么。**

---

## 1. 一句话结论

**当前证据等级 = 「官方规格派生」（spec-derived），没有升到「实机数据独立验证」（hardware-validated）。**

这不是措辞谦虚，是被实测卡住的：Validation 路径已经走完并取得外部日志，但那批日志是仿真器输出，
用它算出的 Wh/km 只是把模型自己的假设读回来一遍 —— 那会产出一个**自洽的假验证值**，比不验证更坏。
所以 §5-D 保持「未锚定」，本文记录的是"为什么停在这里"，不是"下一步就能验证"。

三档口径必须分开讲，混一档就是夸大：

| 档位 | 含义 | 本项目现状 |
|---|---|---|
| **内部一致性** | 产物能被同一份代码逐位重算出来 | ✅ 已达成（两条 `--verify` 门 RC=0，套件绿） |
| **外部可回溯** | 每个被当作事实的数字能点回一个来源 | ✅ 大部分达成（三轴分级登记在 [`真实性审计表.md`](真实性审计表.md)） |
| **实机有效性** | 数值与真实飞行物理量对得上 | ❌ **未达成**，且当前无可用通道 |

## 2. 已锚定（有外部来源，可点开、可复算）

能耗这条链是项目里唯一有官方外部输入的定量链。它的全部外部输入只有 **三个官方数字**：

| # | 外部输入 | 来源 | 等级 |
|---|---|---|---|
| 1 | 单块电池 **1984.4 Wh** | DJI FlyCart-30 官方规格页（DB2000 智能飞行电池） | A / Partial |
| 2 | 空载航程 **28 km** | 同上官方规格页 | A / Partial |
| 3 | 满载航程 **16 km**（载 30 kg） | 同上官方规格页 | A / Partial |

由这三个数派生出项目参数（复算命令见下）：

```
E   = 1984.4 × 2          = 3968.8 Wh        → config: battery_capacity
轻载 = E ÷ 28 km           = 141.743 Wh/km    = 0.141743 Wh/m → config: consumption_base (现值 0.142，差 0.18%)
满载 = E ÷ 16 km           = 248.05  Wh/km
载荷系数 = 28 ÷ 16         = 1.75             → config: battery_load_penalty_factor
```

```bash
# 复算（唯一外部输入是 1984.4 / 28 / 16 三个官方数）
python -c "E = 1984.4 * 2; print(E, E / 28.0, 28.0 / 16.0)"
#   3968.8 | 141.74285714285714 | 1.75
```

**已锚定的其它项**（详见 [`真实性审计表.md`](真实性审计表.md) §1、§2）：

| 对象 | 外部来源 | traceability |
|---|---|---|
| 地图碰撞体（建筑/道路/禁飞区几何） | OSM 底图原件 + sha256 在仓内 | **Complete**（离线可复算普查） |
| 机型速度/载重档 | DJI / 顺丰丰翼 ARK40 官方产品页 | Partial（厂商改版即失效） |
| 风速量级 | Open-Meteo Historical Weather API（再分析格点，默认 Best Match 混合，**未指定模式**） | Partial |

⚠ 厂商网页一律只给 **Partial**：判据是"核验是否依赖别人在线"，不是"此刻 curl 得通"。

## 3. 未锚定（纯内部推导，无外部依据）

| 代号 | 对象 | 现状 | 为什么不能算已锚定 |
|---|---|---|---|
| **D** | 能耗模型的**结构形式**（线性、按距离、无悬停项、无加减速项） | **未锚定** | 全仓**零拟合实现**（见 §4 的普查读数）。0.142 只是"官方两个数相除"，它锚定了**斜率的量级**，没有锚定**公式形状**。真实飞行包线含悬停/爬升/风阻，本模型把它们全折进每米常数。 |
| — | `battery_load_penalty_factor = 1.75` | **半锚定** | 28÷16 是官方数的除法，但"用航程比当功率比"这一步是我的假设：航程受容量/重量双重影响，不纯是功率。第三方交叉证据（悬停 29 min 空载 vs 18 min @30 kg ⇒ 功率比 ≈1.6）落在同量级，仅此而已。 |
| — | 能力匹配权重（载重/速度/续航加权） | **未锚定** | README §已知局限 已声明"仍需通过敏感性实验标定"。 |
| — | 绕行半径 1500 m | **未锚定** | 绝对半径随地图尺度变化，换图需重标；当前取"图跨度 55%"是本地选择。 |
| — | 需求到达过程（任务生成速率/优先级分布） | **部分锚定** | 结构取自即时配送常识，参数无运营数据支撑。 |

### T8 环路普查结论（关键，别把它读成"四条都验证过了"）

上面四个派生量（3968.8 / 0.142 / 1.75 / 248）**不是四条独立证据，是同一组官方数被除了四次**。

具体地：`0.142 × 1.75 = 248` 这个"吻合"是**恒等式**——
`(E/28) × (28/16) = E/16`，28 直接约掉，右边正是同一个派生量本身。
用精确分数（`fractions.Fraction`）验过相等，因此它**不提供任何新信息**。
旧文档把它写成"自洽校验通过"，会被读成"通过了一次独立验证"，T8 已订正为恒等式并标注非校验。

⇒ 推论：**本项目不存在标定（calibration）环节**，只存在规格派生（spec-derived anchor）。
对外表述必须用后者。

## 4. Validation 路径的实际结果（Zenodo 19617182）

### 4.1 做到了什么

| 步骤 | 结果 | 一手证据 |
|---|---|---|
| 修复 HTTP Range 抽取 | 可用（根因是 ZIP 中央目录偏移写错：`u32(40)`→应为 `u32(42)`，40 是 external_attr 后半） | `console/zip_range_extract.py`，夹具用 `zipfile` 当裁判：`header_offset=384`、`u32@40=0`、`u32@42=384` |
| 取得该记录的清单 | `data/raw/px4_logs/manifest.csv`，**与 Zenodo 上的 manifest.csv/content 逐字节相同**（sha256 前缀 `876e5ca895c4fcea`） | 见下方复算 |
| 真 .ulg 规模 | **67 个**，来自 `asi_runs.zip`(52) + `asi-runs-2.zip`(15)，合计 **1526.2 MB** | 本轮 `csv.DictReader` 重扫 |
| 抽样取回并与外部清单对账 | 5 个文件 **md5 5/5 全部吻合** manifest 登记值（尺寸亦逐一致） | `docs/取证输出/px4_ulog_provenance.json` |

**为什么 5/5 对账算"外部证人"**：因为 manifest 本身是从 Zenodo 取的、且与对方持有件逐字节相同，
不是我本地生成的名单。若 manifest 是我自己产的，5/5 吻合就只是自我确认。

```bash
# 复算 1：清单规模与外部一致性
sha256sum data/raw/px4_logs/manifest.csv | cut -c1-16      # 期望 876e5ca895c4fcea
python - <<'PY'                                            # 期望 total=128 / ulg=67 / 1526.2 MB / {asi_runs.zip:52, asi-runs-2.zip:15}
import csv, pathlib
rows=list(csv.DictReader(open("data/raw/px4_logs/manifest.csv",encoding="utf-8")))
u=[r for r in rows if r["path"].endswith(".ulg")]
print(len(rows), len(u), round(sum(int(r["size_bytes"]) for r in u)/1024/1024,1))
PY
# 复算 2：逐文件 md5 对账（期望 5/5 true）
python - <<'PY'
import json, hashlib, pathlib
ok=0
for r in json.load(open("docs/取证输出/px4_ulog_provenance.json",encoding="utf-8")):
    p=pathlib.Path(r["local"])
    if not p.is_file(): print("MISSING", r["local"]); continue
    d=hashlib.md5(p.read_bytes()).hexdigest()
    ok += (d==r["manifest_md5"] and p.stat().st_size==int(r["manifest_size"]))
print("md5+size matched:", ok, "/ 5")
PY
```

### 4.2 为什么它仍然不算验证（决定性发现）

那 67 个日志是 **PX4 SITL + Gazebo 仿真器输出**，不是实机飞行记录。指纹在本轮重新测到（token 级扫描，绕开我一开始写错的报文分帧）：

| 文件 | `SIM_*` 参数数 | `SIM_BAT_DRAIN` | `SIM_BAT_ENABLE` | `SIM_GZ_EC_DIS*` |
|---|---|---|---|---|
| E1_openfield_sig4_seed002.ulg | 170 | ✅ | ✅ | 16 个 |
| E2_nearwall__run03.ulg | 170 | ✅ | ✅ | 16 个 |
| E3_corridor_sig4_seed001.ulg | 170 | ✅ | ✅ | 16 个 |
| E4_nearground__run01.ulg | 170 | ✅ | ✅ | 16 个 |
| E5_rooftop_edge__run01.ulg | 170 | ✅ | ✅ | 16 个 |

`SIM_BAT_DRAIN` / `SIM_BAT_ENABLE` 的含义是：**电池百分比由仿真模型按参数设定速率递减**。
也就是说这批日志里的电量数据本身就是"某个能耗假设的输出"。拿它反推 Wh/km，再把结果拿去"验证"我们的能耗假设，
是闭环引用自己的假设 —— 会得到一个看起来通过、实际什么都没证的数字。

⇒ **决定：不产出该数值。** 消费这些日志的唯一诚实用法是校"结构关系"（姿态/推力/速度之间的相关性），
而它们同样是模型内部关系，仍不及实机。

（附带记录一次我自己的取证弯路，避免下次重复误读：最初两次解析尝试报 `SIM_n=0`，
原因是我用 `b[:16]==magic+version+timestamp` 的定长假设和错误的报文步长去分帧，读到第 2 条报文就跑飞。
真实首条报文是 `'B'` flags（size=40），其后才是格式定义。结论必须以 token 级扫描为准。）

## 5. 下一步行动计划（候选真飞数据源 · 访问状态 · 可行性）

优先级按"能否给出真实 Wh/km 绝对值"排，不按获取难度排。

| 优先级 | 候选源 | 目标机型/载荷 | 访问状态（本轮实测） | 可行性判断 |
|---|---|---|---|---|
| **1** | **CMU M100 数据集（209 次真飞）** | DJI Matrice 100，载荷远小于 30 kg | ❌ **阻塞**：文件本体在 KiltHub，匿名 HTTP **403**，需机构账号/本人浏览器授权 | **唯一真正的候选**：真硬件日志、含 ESC 电流遥测，可算真实 Wh/km。但只能校**结构关系**，绝对值仍不可比（机型/载荷档不同）。需要用户本人完成机构登录下载 —— 这是交付边界，不是技术失败。 |
| **2** | **公开实机 ULog 库（PX4/ArduPilot 社区、各论文附带数据）** | 多为 M100/F450 级别小机 | ⏳ **未开始检索**（本轮止于 19617182 一条记录） | 中：可得真遥测，但普遍**无载重记录** ⇒ 只能校空载能耗斜率，无法校 `battery_load_penalty_factor`。要先做一轮"筛掉含 `SIM_*` 参数"的自动过滤，否则会再次误采 SITL 数据。 |
| **3** | **DJI FlightHub 2 / 上云 API 任务记录** | 与本项目同厂（Matrice 350 / FlyCart-30） | ❌ **不可达**：需企业账号与设备绑定，本机无任何凭证 | 潜在最佳（同厂同机型），但访问门槛最高，且导出通常是航线/时长而非电池毫安时明细。**先问用户是否有可用账号**再投入。 |
| **4** | **Airdata / 第三方商用无人机遥测平台** | 混合机型 | ❌ **不可达**：商业订阅制，无免费公开样本可核 | 低：即便拿到也缺机型一致性，且许可条款可能禁止再分发，与仓内登记冲突。 |
| **5** | **自研实飞测试（借真机飞若干架次，记起飞/降落电量与里程）** | 目标机型 FlyCart-30 级 | ⏳ **未评估**：取决于能否借到设备与合规空域 | **成本最高但唯一能直接锚定 30 kg 档**的路径。最小可行方案：3 架次空载 + 3 架次满载，同起点同航线往返，读电池管理系统原始 mAh。需用户决策资源，不属于我能自行推进的范围。 |
| — | Zenodo 19617182（本轮已取） | PX4 SITL/Gazebo | ✅ 已取得并对账 | **已判定不适用**（§4.2）。保留清单与 provenance JSON 作为"我们查过并且否掉了它"的证据。 |

### 建议的执行顺序

1. 由用户确认 CMU/KiltHub 机构访问是否可得 —— 若能，走优先级 1，并把结果只用于**结构性**校验（明确不得声称校准绝对 Wh/km）。
2. 并行做一次"实机 ULog 筛选"检索（优先级 2），判据固定为：**含 `SIM_*` 参数即淘汰**，此判据已在 §4.2 被证明可执行。
3. 若 1、2 均不通，则正式把 §5-D 记为**永久未锚定**，并在论文/结项口径里改用「官方规格派生 + 结构假设未经实机校验」的表述 —— 这是当前已经在做的口径，不需要改代码。
4. 优先级 5 只在用户主动提供设备时才评估。
