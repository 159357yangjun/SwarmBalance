# 外部确认矩阵（Validation Matrix）

> 用途：把"这个仿真可信吗"拆成**逐子模型**的问题，每个子模型单独指定独立参照、验证指标、
> 判据冻结时点与适用范围。**没有独立参照的那一格不许写"已验证"**，只能写当前证据 + 降级的真实性主张。
> 状态：v0 设计稿（2026-10-06），判据列在实验之前必须填死并另笔提交冻结。

---

## 0. 为什么先拆对象：两个成果不能互相顶替

| 研究对象 | 需要的参照 | 能支持的结论 | **不能**支持的结论 |
|---|---|---|---|
| **飞行物理子模型**（能耗 / 时间 / 轨迹 / 风） | 实飞的速度、载荷、功耗、风况时序 | 飞行时间与能耗的**预测误差** | 多机协同调度是否可信 |
| **协同调度模型**（分配 / 机巢竞争 / 订单到达 / 重规划） | 可独立检验的调度实例、基准求解结果、真实任务过程数据 | 分配约束正确性、算法性能、策略有效性 | 单机能耗是否正确 |

⇒ **拿到 CMU 那 209 次实飞记录，也只证上表第一行。**
真实飞行日志主要携带飞行物理量，通常不含多机任务分配、机巢占用竞争、订单到达过程、调度重规划这些业务事件；
用它给"协同调度系统可信"背书是跨对象引用，是下一篇论文最该避免的逻辑漏洞。

对应到两个研究成果：**A = 无人机调度仿真系统**（业务机制正确、算法确实介入、约束可靠、实验可复现）；
**B = 仿真可信度评估方法**（证据分级 + 验证门 + 异常检测是否比普通流程更容易发现错误）。
A 的软件资产已完整，B 的案例已积累但**缺独立对照实验**（见 §4）。

## 1. 矩阵主表

参照类型三档，**后两档必须降低真实性主张**：

- `R` 真实观测（实飞/实机遥测）
- `I` 独立模型或解析结果（不同实现、闭式解、第三方求解器）
- `C` 受控实验（自造情景，行为可判定，但不涉外部真值）

| # | 子模型 | 当前证据 | 待补证据 | 参照 | 验证指标 | 优先级 | 适用范围声明（待填） |
|---|---|---|---|---|---|---|---|
| V1 | **能耗模型** | 官方规格派生（1984.4 Wh / 28 km / 16 km ⇒ 0.142 Wh/m，差 0.18%）+ 悬停功率比交叉校验（1.61 vs 隐含 1.75） | 不同载荷档 / 速度档的实飞能耗 | R | `Wh/km` 偏差中位数与 90% 区间；载荷分档下的斜率误差 | **最高** | 未定 —— 若只有小机型数据，须写明"仅校结构关系，30 kg 档不外推" |
| V2 | **飞行时间** | 二维匀速运动模型（`drone.py` 每步位移上限 = speed×STEP_SECONDS） | 实飞速度与轨迹时间序列 | R | 逐航段 ETA 绝对误差；总任务时长误差 | 高 | 未定 |
| V3 | **路径模型** | A\* 几何一致性（与直线/绕行半径对比，已有内部门） | 障碍布局独立检查、航线可行性 | I + C | 不可通行段的误判率；绕行解与独立实现的代价差 | 高 | 未定 |
| V4 | **任务生命周期** | 内部行为测试（生成→派发→执行→完成/超时） | 独立业务规则与边界场景（取消、超载拒单、SLA 违约、时钟回拨） | I + C | 边界场景下状态机与独立规则的逐事件一致率 | 高 | 未定 |
| V5 | **机巢调度** | 资源竞争仿真（换电占用、仲裁权重） | 独立事件模型或参考案例（排队论闭式近似 / 离散事件仿真器） | I | 机巢利用率、等待时延分布与独立模型的偏差 | 高 | 未定 |
| V6 | **多算法性能** | 固定场景实验 + 优化器介入已由 `test_g2teeth` 三面证明 | 基准最优/近似解（CP-SAT 或已知最优算例）、配对实验 | I | 与基准解的 gap 分布；配对符号检验（**注意 n=5 时最小 p=0.0625，不构成显著**） | 高 | 未定 |

⚠ 三条纪律：
1. **V1–V2 依赖外部数据，V3–V6 不依赖**。找不到真实参照的部分改用 `I`/`C` 是合法的，
   但相应那一格的措辞必须降级为"与独立实现一致 / 在受控情景下行为正确"，**不得写成"经验证符合真实系统"**。
2. V6 的"优化器介入确认"已完成（Phase 0 收尾），所以它缺的只剩**基准解**，不是从零开始。
3. 每格最后那列现在全是"未定"——**填死它才算实验设计完成**，这是 #65 的第一个交付物。

### 1-bis 误差阈值一律标「未冻结」，除 V6 外

本表所有涉及**真实数据**的误差阈值（V1–V5）当前**都没有依据**，不许填一个看起来合理的百分比。
逐项状态与"还缺什么才能冻结"登记在 [`调度问题数学定义.md`](调度问题数学定义.md) §3。
唯一例外是 **V6 的最优性差距** `gap = (cost_alg − cost_opt)/cost_opt` ——它是纯数学量，
合法性来自定义而非实测，因此可以不依赖外部数据先冻结（阈值本身仍待定）。

### 1-ter V6 已进入第一阶段，且发现必须先裁定一件事

V6 第一阶段（数学定义提取）已交付 [`调度问题数学定义.md`](调度问题数学定义.md)，结论是
**Greedy / PSO / GA / OR-Tools 目前求的不是同一个数学问题**（目标项、决策变量自由度、可行集三处都不同；
OR-Tools 是分配型且不允许弃单，GA 是带顺序+能量约束+可弃单的链式问题）。
⇒ **需要两个基准而不是一个**：`P_assign`（服务 PSO/OR-Tools）与 `P_seq`（服务 GA）。
在此裁定前不写求解器，也不做四算法横向排名。

## 2. 判据冻结规程（防事后挑口径）

顺序强制，违反则该轮结果不作数：

1. **先写判据**：指标定义、误差公式、聚合方式（中位数还是均值）、通过阈值、失败阈值、报告粒度；
2. **再切数据集**：留出**独立验证集**，且切分规则（按环境？按日期？按 seed？）也先写死；
3. **然后才比对**；
4. 比对过程中**不许回头改判据**；确需修订则另起一轮，把旧判据与新判据并列登记，两次结果都报。

配套要求：
- **不许"一拿到飞行日志就拟合参数"**。拟合会把验证集变成训练集，之后任何误差数字都失去意义。
  若确实需要标定，必须先声明标定用哪一部分数据，并保证剩余部分从未参与拟合。
- 判据文件单独一笔 commit（消息以 `[FREEZE]` 开头），后续实验引用该 sha。

## 4. B 侧缺口（与本矩阵并行，不要混做）

本矩阵产出的是 **A 的可信范围声明**。审稿人对 **B** 的问题是另一个：

> 这套可信度评估方法相比无验证措施的普通流程，能多发现哪些原本不易发现的问题？

已有四个真实案例（参数来源脱钩 / 优化器未介入 / 统计分母缺失 / 高度阈值二值化），
但**对照组尚未设计**——怎么构造一个"没有这些措施的普通工作流"、比什么指标、如何避免
"用自己的开发日志证明自己有用"的循环，是 #66 的内容。**在此之前不得声称 B 已被证明有效。**
