# 群智优衡 SwarmBalance · 项目自评报告

> 本文档对项目各模块做阶段性自评，找出问题与缺点，并给出改进路线图。
> 评分口径：1~10 分，10 为可对外发布的工程级水准。

---

## 一、总评

**综合：6.5 / 10**（可达到 8.5 / 10）

项目在**功能完整度**上已经达标（五类算法、禁飞区、任务链、顺路接入、机巢仲裁、双形态可视化一应俱全），但**工程化程度**偏弱——单文件过长、缺测试、依赖被旧版本锁死、前后端有并发隐患。核心算法与仿真逻辑正确，问题集中在"可维护性"和"可复现性"上。

## 三、逐项问题与缺点

### 1. 技术栈（4/10）→ 目标 8/10
- **问题**：osmnx 1.9.4 → Python 3.10 → numpy 1.26.4 的锁死链，安装体验差，队友难上手。
- **方案**：见 `技术栈升级方案.md`，升级 osmnx 2.x + Python 3.12 + numpy 2.x，一条 `pip install` 装完。

### 2. 仿真引擎 environment.py（6/10）→ 目标 8/10
- **问题**：单文件 800 行，同时管任务、无人机、机巢仲裁、路径规划、统计五件事，改动一处易牵动全局。
- **方案**：按职责拆分（`tasks/`、`fleet/`、`nest/`、`routing/`、`stats/`），或至少把 `_manage_berths`、`a_star_pathfinding`、`no_fly` 逻辑抽到独立模块。

### 3. 调度算法（7/10）→ 目标 8.5/10
- **问题**：① 适应度评估仍逐粒子逐任务重算距离（已加缓存缓解，未根治）；② PSO 的偏好矩阵编码本质是"分配+排序"的混合，理论收敛性弱于排列编码，与 GA 的排列编码口径不一致。
- **方案**：① 距离矩阵在 optimize 入口一次性预计算；② 考虑让 PSO 也支持排列编码（或至少在论文里说明两者编码差异对公平性的影响）。

### 4. 任务链 codec（7/10）→ 目标 8.5/10
- **问题**：2-opt 只做反转子段，未做 Or-opt 移位与最优插入；解码是一次贪心扫描，无链间任务交换。
- **方案**：加 Or-opt 邻域 + 链间 relocate（把某链任务移到另一链的更优位置）。

### 5. 禁飞区（8/10）—— 保持
- 独立几何绕飞 + 配置自检 + 场景过滤已相当完整，仅缺"动态/时变禁飞区"（低优先级）。

### 6. console 后端（7/10）→ 目标 8/10
- **问题**：① 并发竞态（已修）；② 无鉴权（本地工具可接受，但部署公网需加）；③ 配置写文件非原子写（崩溃可能损坏 json）。
- **方案**：① 已修；② 加一个简单的 token 或明确文档标注"仅本机使用"；③ 写临时文件再 rename。

### 7. console 前端（8/10）—— 保持
- 交互、可视化、错误提示都到位，仅 3D 用软件投影（pygame）与 Web 用 Three.js 两套渲染并存，风格略有割裂，但功能无损。

### 8. 文档（7/10）→ 目标 8/10
- **问题**：README/CHANGELOG/CONTRIBUTING 已专业，但缺：① 部署文档；② API 文档；③ 论文复现指南（实验参数表）。
- **方案**：补 `docs/部署指南.md` 与 `docs/实验复现.md`。

### 9. 测试（2/10）→ 目标 6/10 —— **最大短板**
- **问题**：几乎无 pytest，全靠 `evaluate_metrics.py` 手动跑 + 肉眼判断。改一处无从回归。
- **方案**：补最小单测集：`chain_codec` 的约束不变式、`no_fly` 的绕飞不穿区、`metrics_schema` 的表头一致性、`two_opt` 的排列合法性。
