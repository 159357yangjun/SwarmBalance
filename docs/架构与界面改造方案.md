# 架构与界面改造方案

> 针对四条不满：① 分层不清 ② 控制层交互不现代 ③ 算法层实现不清晰 ④ 实现层/展示层"很假"且混在一起。
>
> **结论**：问题全部属实。根因不是功能缺失，而是**前端 1795 行单文件 + 后端职责全挤在 `console/server.py`**。
> 本方案**不动现有目录**（避免打断结项脚本与文档引用），用"逻辑分层 + 新增门面 + 拆前端"实现，物理路径保持兼容。

---

## 一、现状核准（先对齐事实）

| 事实 | 数值 | 结论 |
|---|---|---|
| Web 前端 | **单文件 1795 行** `console/static/index.html` | 2D / 3D / 图表 / 面板 / 全部交互逻辑都在里面 → "混在一起"的根因 |
| 图表数量 | **2 个** ECharts 实例 | 只有一条趋势折线 → "数据分析单薄"属实 |
| 右侧面板 | 态势 / 调度 / 对比 / 实验 同挤一个侧栏 | 每个功能只分到半屏 |
| 顶栏 | 算法·Seed·重置·播放·单步·倍速·2D·3D·配置·场景编辑·场景库·引导·＋新任务 **全在一行** | 无分组、无快捷键 → "键位不便利"属实 |
| 后端路由 | `console/server.py` 承担全部路由（meta/snapshot/step/config/scenario/checkpoint/experiment…） | 职责未分域 |
| 几何来源 | 真实 OSM（`part_of_yangpu.osm`） | **数据是真的**，"假"是表现手法问题 |

---

## 二、目标四层架构

| 层 | 职责 | 现状 | 目标 |
|---|---|---|---|
| **L1 算法层** | 纯调度策略：状态 → 分配决策 | `backend_si/`、`backend_wx/pymarl-master/`、`frontend/greedy/` 三处分散 | 统一门面 `algorithms/`：一个 `Scheduler` 协议（`decide(state, config) -> assignment`）+ 每算法一份规格说明 |
| **L2 控制层** | 仿真编排 + 人机交互 | `console/`（路由不分域）+ index.html 里的 UI 逻辑 | 后端按域拆路由（sim / scenario / experiment / data）；前端按"工作区"组织 + 快捷键 + 命令面板 |
| **L3 实现层** | 仿真内核 + 可视化渲染 | `frontend/`（环境/实体/路径）+ 2D/3D 绘制 | 内核与渲染解耦；渲染用真实 OSM 几何 + 像样材质与模型 |
| **L4 数据展示层** | 指标承载 + 统计分析 | 只有"态势"页 + 1 条折线图 | 独立"数据分析"工作区：多维图表 + 原始数据浏览器 + 数据来源与口径 |

---

## 三、四条不满 → 具体改造项

### P0（先做：收益最大、风险最低）

**1. 拆分前端单文件（1795 行 → 多模块）**

```
web/
├─ index.html          骨架（< 150 行）
└─ js/
   ├─ api.js           REST 封装 + 轮询
   ├─ state.js         全局状态（算法/seed/快照/选中）
   ├─ view2d.js        2D Canvas 渲染
   ├─ view3d.js        Three.js 渲染
   ├─ charts.js        ECharts 图表（多实例）
   └─ panels/*.js      各功能区面板
```
- 用**原生 ES module**，不引入构建链路，保持"双击即跑"
- 验收：`index.html` < 150 行；单模块 < 400 行

**2. 顶栏按域分组 + 加键盘快捷键**

| 分组 | 内容 |
|---|---|
| 运行 | 算法 · Seed · 重置 · 播放/暂停 · 单步 · 倍速 |
| 视图 | 2D / 3D / 分析 |
| 场景 | 配置 · 场景编辑 · 场景库 |
| 实验 | 一键实验 · 证据包 |
| 帮助 | 使用引导 |

| 快捷键 | 动作 |
|---|---|
| `空格` | 播放 / 暂停 |
| `←` `→` | 单步 退 / 进 |
| `1` `2` `3` | 切 2D / 3D / 分析 |
| `R` | 重置 |
| `F` | 聚焦选中实体 |
| `Ctrl+K` | 命令面板（搜功能） |

- 验收：高频操作**全部可不用鼠标完成**；顶栏按钮 ≤ 8 个，其余收进「更多」

**3. 新增独立「数据分析」工作区（L4 正式界面）**

- 子页签：**概览 / 时效 / 资源 / 能耗 / 机巢 / 分布 / 原始数据**
- 图表（≥ 8 个，独立实例）：
  完成率趋势 · 超时率趋势 · 时延箱线图 · 机队利用率时序 · 机巢泊位热力图 ·
  任务重量分布直方图 · 机型负载对比 · GA 收敛曲线（含局部搜索改进量）
- 原始数据浏览器：**任务表 / 无人机表 / 事件日志**（可筛选、可导出 CSV）
- 验收：图表 ≥ 8；分析界面**与地图不再同屏混排**

### P1

**4. 算法层规格化（L1）**

- 定义统一 `Scheduler` 协议；每个算法补齐规格文档：**输入 / 输出 / 超参 / 复杂度 / 伪代码**
- 前端加「算法」面板：显示当前超参、迭代/收敛、单步决策耗时
- 验收：新增算法只改一处注册；任一算法都能对着文档读懂

**5. 界面视觉规范化（L3 表现）**

- 抽取设计令牌（色彩/间距/字号/圆角/阴影）为 CSS 变量；统一按钮 / 卡片 / 表格 / 表单样式
- 验收：全站无硬编码颜色；支持深/浅主题切换

### P2

**6. 2D / 3D 拟真化（L3）**

| 项 | 现在 | 改造后 |
|---|---|---|
| 2D 底图 | 空白 + 线段 | 叠加真实**道路 / 水系 / 绿地**（OSM 矢量，离线可跑）；建筑按轮廓 + 高度做明暗 |
| 3D 建筑 | 单色白模 | 真实高度 + **分区材质**（住宅 / 商业 / 工业）+ 阴影 |
| 3D 场景 | 只有地面 | 加道路、绿地、天空渐变 |
| 无人机 | **一个球** | 带航向的**机体模型** + 旋翼动效 + 航迹拖尾 |

- 验收：**截图不看 UI 也能认出这是真实城市**

## 四、专治"感觉很假"（数据可信度设计）

| 措施 | 说明 |
|---|---|
| 几何真实性 | 建筑轮廓/高度、道路、水系全部来自 OSM；UI 角落常驻"数据来源：OpenStreetMap" |
| 机型真实性 | 三机型参数标注来源（美团 / 顺丰丰翼 ARK40 / 大疆 FlyCart 30 公开规格） |
| **把"模拟过程"本身可视化** | 任务生成的时间分布、热点分布、重量分档抽样、到达间隔 —— 让评审看到**随机是按分布抽的**，不是拍脑袋 |
| 可复现证据 | 界面显示当前 seed / 生成参数 / 数据哈希，与 `reproducibility.json` 对齐 |
| 参数与口径面板 | 一键查看"本次仿真用到的全部参数 + 每项来源" |

---

## 五、风险与节奏

| 风险 | 说明 | 对策 |
|---|---|---|
| 目录大重构 | 会打断 `release_check` / `selfcheck` / 文档引用 | **不动目录**，用逻辑分层 + 新增门面实现 |
| 前端拆分 | 改错白屏 | 拆完先跑 JS 语法 + 无头渲染校验 |
| 拟真化 | 资源体积、离线可跑 | 只用 OSM 矢量 + 程序化材质，不引入大贴图/大模型 |

**建议节奏**：P0 → P1 → P2。P0 完成即可显著改善"结构不清 + 交互不便 + 展示单薄"三条。
