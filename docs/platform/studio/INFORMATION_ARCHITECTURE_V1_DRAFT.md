## 1. 产品定位与一级导航

**唯一产品目标：异构无人机配送的可操作仿真平台。**
框架、场景资源、规则/事件、运行记录和回放优先；暂不开发新调度算法、数学优化引擎或通用三维 GIS 建模器。

用户操作顺序：**项目 → 场景 → 运行 → 结果**。

一级导航严格四个工作区：

| 一级区 | 工作对象 | 必需功能 | 不放在这里 |
| --- | --- | --- | --- |
| 项目 | Project、资源清单、场景模板与修订索引 | 新建/复制/打开/导入导出项目；资源总览；历史工作记录 | 运行时调度、场景空间对象逐个编辑 |
| 场景 | Asset、WorldRevision、ScenarioRevision、实体草稿与规则 | 地图/场景文件导入、在线选区、图层、区域、机巢、机队/无人机定义、订单/需求、空域、风及环境、事件计划、场景校验、保存修订 | 播放/暂停/实时故障、历史指标 |
| 运行 | Run、WorldState、RunRecord（进行态） | Run 前能力预检、参数/组件选择、开始/暂停/继续/单步/停止、状态地图、任务池、机巢队列、任务链、实时事件注入、运行日志、检查点 | 修改 World 和已发布 Scenario、批量对照图 |
| 结果 | 只读 RunRecord、历史指标与可比较实验集合 | Run 列表、时间回放、对象事件下钻、指标趋势、可比较性校验、实验批次与归档导出 | 实时场景编辑、直接改变历史结果 |

**右上角不是一级页面**：设置（数据源/缓存/插件/本机环境/性能），帮助（`/spec`、操作指南、快捷键、诊断）。日志中的开发调试仅从诊断打开。

原则：一级导航表示用户的高层任务，**配置是操作上下文，不是单独一级页面**；地图只是一种场景资源/工作画布，2D/3D 是显示模式，算法是执行组件。

## 2. 当前实际页面与功能盘点

- `/` 原控制台顶部含算法/Seed、重置/播放/单步/速度、2D/3D、配置、场景编辑/库、引导、新任务；主侧导航“实现/控制/算法/数据/规范”；主地图带无人机/任务/机巢的 Inspector；
  运行调度页含任务流、任务池、机巢队列、任务链、故障/机巢关闭与恢复、事件日志；
  指标页混有演示场景、快照、运行概览与趋势；
  算法页含比较结果和批量实验；
  场景布局和场景库在弹窗；
- `/workbench`：Project/Configuration/Execution/Results 四页，但配置为长表单，当前地图固定杨浦，运行只支持 Greedy；
- `/map-lab`：在线地图、区域选择、按选区 OSM 请求、缓存、图层叠加与质量警告，仅 GIS 预览；
- `/spec`：仿真软件设计规范独立文档；
- 后端：`/api/scene-library` 持久化的是初始场景配置，`/api/checkpoints` 是进行中的状态节点，`/api/scenarios` 为演示脚本，`/api/experiments` 是批次任务，不能因为都叫“场景”就合并数据模型。

## 3. 应用公共外壳与空间尺寸

桌面优先（默认目标宽 1440、1366；需在 1920 及缩窄窗口复测）：

- 全局导航：左侧窄竖栏 64–72px，固定四个对象工作区的入口，不提供多级侧边导航迷宫。
- 顶栏：56–64px，项目名称/面包屑/World修订/Scenario修订、保存状态、运行态和“保存修订/准备运行”上下文动作；不用全局常驻“播放”按钮。
- 次工具栏：44–48px，**只展示当前工作区与选中对象的相关工具**。
- 场景画布：左侧对象树约 220–260px；中间地图/二维场景画布自动伸缩，设计目标宽度至少约 55%；右侧选中属性 Inspector 280–340px，可隐藏/浮出。
- 底部任务/事件/日志区 160–220px，可收起；默认不占据场景编辑画面，导入/运行/回放时按任务展开。
- 宽度不足约 1280px 时优先收起右侧面板，进一步缩小时收起对象树；始终优先主画布，不是等比例压小所有区域。
- 重要：上述数值是设计目标，需真实 G3 截图/可达性测量验证。

## 4. 四个工作区具体线框与交互

### 4.1 项目：管理工作，不用地图填满首屏

```text
┌─ 全局导航 ──┬── 项目                                  [新建] [导入] ┐
│ 项目（选中） │ [项目搜索 / 最近 / 模板 / 我的场景]                    │
│ 场景         ├───────────────┬─────────────────────────────────────┤
│ 运行         │ 项目列表       │ 选中项目概览                         │
│ 结果         │ A / B / C     │ 地图资源 / World版本 / 场景版本      │
│              │ 最近打开      │ 最近Run / 未保存状态 / 异常提示      │
│              │ 模板          │ [进入场景] [打开运行] [查看结果]     │
└──────────────┴───────────────┴─────────────────────────────────────┘
```

对象：Project。场景模板和预设是“从模板创建”的来源；导入资源可由此开始，但完成映射后返回场景画布。没有选中项目时解释“先创建项目”，而非展出大量空仪表盘。

### 4.2 场景：整个系统最大的工作画布

```text
┌─ 项目名 / World r2 / Scenario r7 / 未保存    [保存修订][校验][准备运行] ┐
│ [导入地图/场景] [选择] [机巢] [任务] [禁飞区] [测量] [2D/3D]     │
├──资源/对象树─────┬──────────────────────────────┬──上下文 Inspector──┤
│ 地图数据与图层   │                              │ 选中机巢 N-02       │
│  ├底图           │        主 地 图 画 布         │ 坐标、泊位、静态能力 │
│  ├建筑/道路      │   机巢、任务区、限制直接显示  │ 数据来源、约束检查  │
│  └World覆盖范围  │                              │ [应用草稿][删除]     │
│ 设施/机巢        │                              │                    │
│ 机队/机型定义    │                              │                    │
│ 任务与需求源     │                              │                    │
│ 空域与限制       │                              │                    │
│ 环境/风          │                              │                    │
│ 规则及事件计划   │                              │                    │
├─────────────────┴──────────────────────────────┴────────────────────┤
│ [按需展开] 导入进度 / 数据质量 / 校验错误 / 编辑历史                │
└─────────────────────────────────────────────────────────────────────┘
```

地图准备并非另一主页面：地图资源节点 → 【导入 GIS】选择本地 OSM/GeoJSON/GPKG/已有场景或在线选区；由导入向导依次展示来源/格式/坐标/质量/预览/确认。**尚未实现的格式按规划标注，不显示可点击伪按钮**。

场景编辑保持同一画布：添加机巢点击地图 → Inspector 修改；机队型号及数量通常在机巢/机队上下文配置；任务来源、任务区、禁飞区利用绘制工具；环境/规则/事件计划根据对象性质放于树节点，不做与场景无关的“设置大全”。

修改 World 静态几何及机巢定义产生新 World 草稿/修订；改变初始状态、任务流和事件计划产生新 Scenario 修订（最终字段归类受待冻结契约约束）。已被 Run 引用的版本不可原地覆盖。

### 4.3 运行：行为与资源调度，不是场景编辑器

```text
┌─ 项目名 / 固定World & Scenario / Run ID / 执行组件   [配置运行]        ┐
│ [开始][暂停/继续][单步][停止]   时间 t=...   速度×1/×2/×5       │
├──对象状态列表──┬───────────────────────────────┬──状态详情 Inspector─┤
│ 无人机 D-*     │       地图与动态轨迹           │ D-03: 电量/载重/状态│
│ 任务池 T-*     │       航线/事件发生位置        │ 任务链/目标/约束    │
│ 机巢 N-*       │                               │ [注入允许的事件]     │
│ 预设事件       │                               │                     │
├────────────────┴───────────────────────────────┴─────────────────────┤
│ [展开] 任务分配事件 / 资源队列 / 故障与恢复 / 调度日志 / 检查点      │
└──────────────────────────────────────────────────────────────────────┘
```

运行前配置（只在“准备运行”侧抽屉中）：选择 World + Scenario 的不可变版本、启用的组件、仿真时长/步长、可用测试适配器、Seed、能力检查、失败策略。参数只出现在相关组件上下文，不要求用户绕一圈打开全局“配置”。

运行时点击实体只读详情；故障、临时禁飞、订单注入、机巢关闭/恢复要形成**明确记录的 Run 事件**。检查点属于 RunState，只在运行里提供保存/恢复；不可等同场景模板或静态修订。日志底栏支持从错误时间定位到地图对象。

**避免误判**：尚未验证物理和调度模型时可选择“确定性演示适配器”，显示“演示”且不产生可信飞行与算法结论。旧系统算法暂留在旧路径运行，直到正式兼容。

### 4.4 结果：运行记录与实验批次合并

```text
┌─ 项目 / 结果             [历史Run] [双Run对比] [批量实验] [导出]  ┐
├─筛选与运行列表───────┬───────────────────────────────────────────┤
│ Run ID / 状态       │ 当前选择 Run 的概要、质量和版本一致性      │
│ 场景版本            │ 指标总览 → 轨迹回放 → 事件/任务下钻        │
│ 算法/组件            │ 时间轴与地图状态同步                       │
│ 时间范围            │ 条件不兼容时明确标记，不做算法优劣排名      │
│                      │ 来源、Seed、日志、证据包                   │
└──────────────────────┴───────────────────────────────────────────┘
```

结果页不是直播监控页面。三个局部模式：**单次 Run 详情 / 多 Run 对比 / 实验批次**，仍共享同一结果对象与筛选状态，避免另起“算法页、数据页、结果页”。

## 6. 数据语义与页面一致性

- 项目当前上下文：`project_id`。
- 场景上下文：`world_id + world_revision` 和 `scenario_id + scenario_revision`。
- 运行上下文：`run_id`，只从冻结的输入版本装配 `RunSpec`；同一轮 Run 的世界/场景只读。
- UI 选择：`selected_object_id` 与 `mode`、`viewport`、`dirty`，**不能**当作计算世界权威状态。
- 导入原始资源、已验证 World、编辑草稿、运行检查点、历史结果具有不同生命周期和权限。
- 所有异步网络响应按项目/场景/请求代次校验，不把 A 项目下载的图层显示在 B 项目。
- “2D/3D”、“地图底图类型”只改变视图，不改运行输入。
- 导入的 3D mesh 不默认为有效的飞行障碍；OSM 预览包必须通过计算数据质量门才能供正式 Run 使用。

## 7. 无重复入口和状态规则

每项操作只有一个主要业务实现，可有多个上下文快捷入口，但必须调用同一服务与校验。例如从项目和场景均可“导入场景”，最终进入同一个导入向导；不能出现两个互不兼容的保存器。

按钮有规范状态：空/不可用、加载、成功、失败、取消、撤销/恢复；运行中的编辑按钮必须解释为何不可用。

全局模式切换应保存场景草稿或提示未保存内容，不得暗中丢失。结果页打开的是只读历史，不可以顺手改写已发布 Scenario。

## 8. 设计先行的开发/迁移顺序

1. 审核本 IA 与项目/场景/运行/结果的主任务；补齐用户实际常用工作流。
2. 先统一项目/资源/场景上下文的数据契约与导航骨架，**不**同时重写旧运行器。
3. 场景画布迁入地图、对象树、属性检查器和导入任务；完成保存/恢复。
4. 运行工作区接入正式时钟/事件/状态接口（**必须先解决 ARCH-06 当前 HOLD 的接口冻结问题**）。
5. 结果页面统一旧历史结果、Run 记录与只读回放；最后对比实验、模型和算法深化。
6. 完成真实 G3：两屏幕尺寸+窄窗口、键盘、失联恢复、导入坏数据、保存/重开、Run 只读、回退原路径；提供原控制台功能逐项覆盖表，达成后再讨论替代入口。
