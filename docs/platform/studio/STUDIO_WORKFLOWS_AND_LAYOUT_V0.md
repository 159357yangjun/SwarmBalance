# Studio G0/G1 — 统一控制台与地图操作流程（候选设计）

> 状态：G0/G1 设计草案；无 G2 已实现 / G3 人工端到端通过声明。
> 主模式采用 TaskUI v1 的 Object Management + Monitoring/Analysis；避免多个不相关的地图页面和仪表盘卡片。

## 1. 用户与核心任务（G0）

目标用户：无人机物流配送仿真研究者与工程人员。
默认桌面 Web，本地服务；后续可连接远程计算节点。

| 任务 | 起始状态 | 操作序列 | 用户可观察完成条件 | 出错恢复 |
|---|---|---|---|---|
| 新建项目和准备世界 | 无项目/有项目 | 新建 → 导入地图或使用空白环境 → 检查坐标/数据 → 发布 World revision | 能重复打开 World、查看资源来源/质量/版本 | 未验证保留草稿、重试导入、不覆盖版本 |
| 编辑配送场景 | World 可用 | 放置机巢/任务/机队/限制 → 选中属性面板编辑 → 校验 → 保存 Scenario revision | 关闭/重开仍可看到相同布局、规则和对象稳定 ID | 撤销编辑或从已有修订恢复 |
| 完成一个基础运行 | Scenario 已发布 | 选择运行配置/组件 → 能力校验 → 启动 → 暂停/单步/继续/停止 | 运行状态、时间轴和日志与界面一致 | 停止、失败留痕、受控重跑 |
| 检查和回放结果 | Run 存在 | 选择 Run → 时间轴定位 → 地图/对象/日志联动 → 导出 | 能查到选中时刻的一致状态和引用版本 | 只读回放、提示缺失数据，不假装可回放 |
| 导入外部场景 | 本地文件或现有项目 | 选择文件 → 校验格式/单位 → 字段映射 → 预览变更 → 确认导入为新修订 | 源文件不被改写，资源 provenance 可查看 | 取消、拒绝、不兼容项逐条报错 |

## 2. 唯一应用外壳（G1）

一级导航 **项目 / 场景 / 运行 / 结果**，不独立增加“地图平台”“模型平台”“GIS 平台”一级标签。平台设置、帮助和数据源管理用按需菜单。

```text
┌─ SwarmBalance ─ 当前项目 / World revision / Scenario revision ─●未保存 ──────────┐
│ 项目   场景   运行   结果                  [保存修订] [校验场景] [准备运行] │
├──────────────────┬──────────────────────────────────┬────────────────────┤
│ 场景资源与对象树  │ 主地图/场景画布                     │ 当前选中对象检查器  │
│ 地图图层          │ [选择][放置机巢][任务点][禁飞区]    │ 名称、位置、规则    │
│ 机巢与设施        │ 地图底图或导入模型 + 可交互实体     │ 校验/错误/来源      │
│ 机队定义          │                                  │ 保存/撤销           │
│ 任务与事件        │                                  │                    │
│ 空域和环境        │                                  │                    │
├──────────────────┴──────────────────────────────────┴────────────────────┤
│ [可收起] 导入任务 / 属性变更记录 / 错误与警告 / 运行事件 / 时间轴            │
└───────────────────────────────────────────────────────────────────────────┘
```

主画布尽量占剩余宽度（初始设计目标约 55–65%，需真实视口测量），左侧对象树约 220–260px，可折叠；右侧检查器在有选中对象时显示约 280–340px，未选择时收起。运行/结果工作区复用对象检查器，不再重复实现同一对象的详情弹窗。

## 3. 地图不是固定编辑器、也不是复杂 GIS

地图工具按模式按需出现：

- **准备地图**：通过“导入资源”统一入口选择 OSM/GeoJSON/GeoPackage 或在线选区（当前 Overpass 下载是小区域预览）；选择资源 → 校验坐标/边界/缺失信息 → 生成 World 版本。**在线底图**的平移缩放不改变 World 边界；明确“选择研究区域”后才更新选区。
- **编辑场景**：选择/移动机巢、配置无人机及配送任务、绘制禁飞区；地图图层通常只读；属性面板绑定对象 ID；批量数据从文件导入。
- **运行**：地图画布显示状态/轨迹/任务流，编辑模式自动退出；按需显示时间控制条和事件/资源检查器，运行中的人工操作被记录为事件，不直接更改静态 World。
- **回放**：只读时间轴、事件筛选、对象详情；对历史结果不提供实时修改按钮。

专业建模交给 QGIS/Blender/Gazebo 等外部工具；只支持被声明/校验的格式与含义，外部 3D mesh 默认仅用于渲染，不隐式等价于飞行碰撞模型。

## 4. 工作模式与重要按钮

- “导入场景”是场景资源的对象级操作，不是独立主页面；导入时展示格式检查、坐标映射与冲突项，确认后生成草稿。
- “保存修订”作用于当前 World/Scenario 草稿，标记未保存变化，不覆盖已发布版本。
- “准备运行”先执行资源/能力/规则检查；出现失败列表和定位链接时不启动。
- “开始/暂停/单步/结束”只在运行模式展示；实时编辑同一区域禁用，非编辑型查看始终允许。
- “结果回放”从某一个 Run 进入，返回场景时保留选中项目和地图视野。
- 支持键盘操作：Tab/焦点、Escape 取消临时绘制、Delete 删除**草稿中**选中的对象、Ctrl+Z 撤销草稿操作（实现时与输入框快捷键隔离）。

## 5. 必须统一的前后端状态

前端：`active_project_id`, `active_world_revision`, `active_scenario_revision`, `mode`, `selected_object_id`, `viewport`, `dirty`, `validation_report`, `active_run_id`。
这些是 UI 状态引用，**不作为后端 WorldState 的权威数据**。打开不同项目必须清理旧对象选择和异步请求；项目级缓存必须按 ID 隔离。

后端：Project/Asset/World/Scenario 的持久版本为编辑权威数据；Run/WorldState/RunRecord 归运行引擎管理。现有 MVP 只有杨浦 + Greedy，禁止把新的 GIS 预览包传进旧 Runner 冒充正式场景。

## 6. 需要走查的 G3 任务

1. 新建项目、导入合法资源、检查 World、保存、重开，无信息丢失。
2. 选择场景对象、修改机巢属性、撤销、保存，再打开属性一致。
3. 有效/无效区域输入和未知建筑高度均有清楚的反馈；不能将空数据当“无障碍”。
4. 配置没有计算模型时显示“不能运行”或“仅演示”，不显示伪科研指标。
5. 运行中暂停/继续/单步的时间、对象状态、事件日志可对齐。
6. 浏览器刷新/服务重启/网络断开后，不覆盖历史运行，不伪称恢复成功。
7. 在 1366×768、1920×1080、窄窗口下检查真实布局；核验键盘和焦点。
8. 原 `/` 和 `/workbench` 旧操作不退化，尤其历史结果只读和 `legacy_direct`。

## 7. 入口放置决策

- 地图导入与选区：场景画布的“资源/导入”工具，而不是永久 GIS 侧栏。
- 对象编辑：画布选中 → 右侧检查器，常用创建工具位于地图上下文工具栏。
- 配置与规则：选中对象或 Scenario 的上下文属性，不堆叠复杂的全局设置首页。
- 运行/回放：单一顶层模式切换，隐藏不相关的编辑工具。
- 低频系统参数/插件：项目设置和资源管理器按需打开。
