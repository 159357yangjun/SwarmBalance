# SwarmBalance Studio — 框架优先产品与技术基线 v0.1（待审核）

> 状态：设计候选；不是“架构已冻结”或“仿真可信”声明。
>
> 基于 `master@e7297f7813230e8fcce76b453bb08ea288aad8b3` 的源码检查；本文件只确立产品级边界和独立开发节奏，不替代 ARCH-01～06 的尚未会签 ABI。任何涉及事件提交/时钟的接口待 ARCH-06 争议解除后才能冻结或接入正式 Run。

## 0. 唯一产品目标

构建面向**异构无人机物流配送**的仿真平台。平台的第一版工程成功条件：
“用户能创建/导入项目与场景 → 检查并设置地图和实体 → 配置规则与事件 → 使用基础、确定性的执行适配器控制运行 → 查看状态、轨迹及事件 → 保存并回放运行记录”。

重点是**平台工作流、对象/资源模型、规则、运行生命周期和操作完整性**，不是比较 GA/PSO/Greedy 的最优性，也不是重建 QGIS/Gazebo 的专业地形建模功能。

不把地图浏览页视作仿真世界，也不把测试数据的运动视作已验证的无人机物理飞行。

## 1. 已实现资产与主要断点

- `/map-lab`: MapLibre 在线底图，区域框选、小块 OSM 导入、缓存/预览 GeoJSON；`console/gis_import.py` 标注 `simulation_safe=false`，仅处理 OSM way，不完成关系多边形、DEM 与计算地图质量门。
- `/workbench`: 项目/配置/运行/结果，`console/mvp_service.py` 中 `defaults().map=yangpu`，`_validate` 会丢弃展示用 `map` 字段；运行分支只接受 greedy 和已有地图。不可假装支持任意 World。
- `/`: 旧指挥台含部分实体编辑、运行单步/暂停、任务注入、故障事件和结果交互，需要拆解复用，不应删除。
- ARCH-06 目前仍为 HOLD / NO-FREEZE。新框架先作为 opt-in 的独立模块与新工作区设计推进，保持 `legacy_direct` 默认不变。

## 2. 建设边界：做什么 / 不做什么

| 领域 | 平台第一阶段承担 | 使用成熟工具 / 以后再做 |
|---|---|---|
| 地图 | 导入、场景引用、图层管理、坐标/几何/数据质量验证、必要空间索引 | 不自行开发完整 GIS 编辑器、商业瓦片平台和全球三维地球 |
| 三维 | 提供导入外部模型接口，显示场景对象，明确视觉模型与计算几何区别 | 不自行制作复杂城市模型、材质与物理材质编辑器 |
| 实体 | 统一 ID、类型、静态定义、起始状态、事件与属性检查器 | 不把某个机型硬编码到 World 基类 |
| 规则 | schema 约束、时间/事件、资源占用、变更的前置条件、失败策略 | 不提前重写现有调度/路径算法 |
| 运行 | 生命周期、时钟、step/暂停、状态提交、追踪、快照、回放 | 无算法时用声明式确定性脚本/基础运动测试适配器；不能声称航空动力学有效 |
| 科研 | 保留所有运行输入版本、变更与运行记录；支持比较入口 | 真模型校准、复杂算法优化、统计/不确定性结论最后阶段 |

## 3. 八个核心概念（避免互相冒充）

1. **Project**：工作空间、资源索引、工作状态；可以修改名称和引用，不作为执行模型。
2. **Asset**：OSM/GeoJSON/GeoPackage/外部场景/脚本等带原始格式、授权来源、内容摘要的资源；未经验证不能作为计算几何。
3. **World revision**：选定地理/合成空间、CRS、边界、不可变静态实体与规则集合；空间数据质量/能力是显式字段，缺失高度不代表 0。
4. **Scenario revision**：引用具体 World 版本，定义初始状态、对象布置、外部输入、事件表和规则参数；每次保存修订得到新版本。
5. **Component**：数据源、空间服务、事件源、运动模型、调度器等实现插件；仅通过声明的能力引用，运行框架不能 import 具体算法。
6. **RunSpec**：冻结 World/Scenario/组件版本、启动参数、时间设置、种子以及外部资源的运行请求；具体 canonical digest 依赖待冻结契约。
7. **RunState**：运行中的随时间变化状态，仅由统一运行协调者提交；编辑器不得直接修改。
8. **RunRecord**：Run 的事件、状态帧、错误、操作指令与资源证据；可供只读回放和追溯。

禁止在 `Project` 文件里同时存地图图片、实体运行状态和当次实验结果。不得将同一旧 `simulation.json` 直接改名成 World/Scenario 而宣称完成迁移。

## 4. 框架规则：第一阶段必须有的行为约束

- 身份：项目/资源/World/Scenario/Run/实体具有稳定 ID；实体引用必须可检查，不能靠列表索引。
- 版本：已被 Run 引用的 World 和 Scenario 为只读版本；编辑只产生新修订，不静默改历史值。
- 空间：经纬度/米坐标、坐标轴顺序、CRS、水平/垂直单位及数据覆盖范围显式声明；无定义则禁止声称精确空间计算。
- 导入：源文件不直接变更旧仿真数据；先检测类型、安全、CRS、几何、超限与许可证，再预览、确认、固化；非法对象展示结构化错误。只信任许可目录/经过安全处理的导入副本，不接收任意磁盘路径。
- 实体：静态属性、初始状态与运行状态分离；对象增删、属性修改、批处理要有校验、保存状态和撤销或版本恢复。
- 时间：运行使用单一仿真时钟与确定性事件排序；暂停不得推进仿真时间；单步只承诺一个定义清楚的推进边界；事件状态不可被 UI 偷偷提交。具体提交 ABI 待 ARCH-06 冻结。
- 生命周期：草稿 → 已校验 → 已准备 → 运行中/暂停 → 完成/失败/停止；不允许跳过场景/资源能力门。失败要留记录、可重试或回退、绝不伪装为完成。
- 组件：插件必须声明输入、输出、单位、能力、版本、生命周期和错误语义；`UNSUPPORTED_CAPABILITY` 必须显式阻止运行，不可返回空结果冒充执行过。
- 结果：时间线、事件日志、轨迹要绑定 Run 和不可变资源；回放只读，不回写编辑器和历史结果；演示级轨迹不得显示为已验证飞行。
- 兼容：现有 `/api/*`、MVP 项目/Run、杨浦 `legacy_direct` 及冻结实验数据均保持可用；迁移只通过新版本与显式适配器进行。

## 5. 从完整产品到最小实现的分层

```text
客户端：统一 Project 工作空间 / Scene Studio / Run Studio / Result Review
                         |
应用服务：ProjectService / AssetImport / WorldCatalog / ScenarioCatalog / RunController
                         |
资源与版本层：数据清单 + immutable World/Scenario revisions + 文件/对象仓库
                         |
平台引擎：Harness / EventCoordinator / Clock / StateStore / Snapshot / Recorder
                         |
能力适配层：Spatial / DataProvider / EventProvider / Dynamics / Scheduler
                         |
运行实现：确定性测试适配器（平台期） | LegacyAdapter（受控兼容） | 未来真实模型及算法
```

**绝不**先把真实地图直接塞进旧 `SimSession.osm_path` 当作框架完成，也不为了新首页把所有旧代码一次性迁移。

## 6. 框架完成的可观察标准

工程完成不等于科研可信。首先证明用户在一处工作空间完成：
- 由现有项目新建一个场景，导入外部合法地图数据或空白世界；
- 检查数据能力、选取图层、布置机巢、机队和任务/规则；
- 保存、关闭、重开后所有对象 ID、位置、事件和版本一致；
- 通过“场景校验”后执行一个**明确标为演示级**的确定性运行；
- 暂停/继续/单步、事件结果、失败状态、停止/重试能解释；
- 浏览轨迹、查单架无人机或任务状态、拖动时间轴回放；
- 导出 Run 关联的资源版本和完整记录；
- 另开项目不污染当前运行；原杨浦旧路径的冻结产物不变化。

测试的作用仅是工程检查；飞行物理准确性、地图障碍完整性和算法性能以后独立审定。
