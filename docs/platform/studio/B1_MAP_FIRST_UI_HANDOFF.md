## 对照用户反馈：为什么不是四页面+窄侧栏

旧设计的问题：固定深色导航＋固定二级侧栏＋右侧属性＋底部表格，把画布挤成了一个小区域，属于传统网页后台思维。

新设计的基线：
1. 默认全屏地图（除约 58px 顶栏和 34px 状态栏）；没有常驻深色导航和任何常驻侧边栏。
2. 顶栏只有 SwarmBalance、项目与文件菜单、数据准备、旧版杨浦仿真入口。
3. 地图上小工具带：图层 / 选区 / 开始选区 / 活动；按钮打开浮动侧抽屉，地图不重新排版。
4. 资源抽屉只显示真实可叠加的建筑、道路、水、土地利用、铁路和数据质量，点击开关立即改变图层可见性。
5. 选区抽屉复用真实 bbox、视野、佛寺镇恢复、分块 OSM 导入、取消、进度与缓存。
6. 在已下载的地图要素上点击才弹出右侧只读属性；空白处/关闭按钮收回。
7. 底部日志默认隐藏，点击活动按钮/状态栏展示真实操作日志，支持关闭。
8. Esc 可取消选区、关闭面板与项目菜单；键盘 Tab 可达。
9. 不提供虚假的三维、保存 World、编辑机巢、规则表单；当前 GIS 包依旧 `simulation_safe=false`，顶部明确标记“未绑定仿真项目”。
10. 点击“旧仿真”进入旧杨浦页面，并明确不使用当前 OSM 地图包。项目管理菜单进入现有 `/workbench`，不是声称已实现项目-地图绑定。

## 实际状态

- 地图按需下载仍受小区域面积、缓存和公网 Overpass 限制。
- 页面重构实现的是**GIS 地图工作区的第一批界面外壳**；更大的目标（Project/World/Scenario 绑定、物流对象 Inspector、Run 模式切换、事件/结果回放）还未迁移。
- 当前无需新前端框架和大型构建系统；复用 MapLibre CDN、FastAPI 模块、既有 JS。后续统一功能外壳前须解决 ARCH-06 HOLD 的跨组数据契约。
- 已加 DOM 契约测试并沿用 GitHub CI 的 JS `node --check` 和 Python smoke；**不把这说成已完成真实浏览器 G3 验收**。

## 人工 G3 走查清单

1. 打开 `/map-lab` 后左侧没有常驻导航栏或资源树；地图覆盖主要工作区。
2. 点击“图层”和“选区”，抽屉显示/隐藏；地图不变窄，Esc 关闭。
3. 两点框选与输入经纬度互相同步；越界不更新合法 bbox，不允许错误下载。
4. 1×1km 下载可显示进度、成功图层和缓存复用；关闭面板后地图仍可操作。
5. 点击建筑/道路打开只读属性，空白地图与叉号关闭。
6. 点击“活动”显示记录，刷新页面后可恢复本会话之前的地图包（缓存仍在服务器时）。
7. 下载期间修改选区，旧任务结束不得覆盖新范围。
8. 检查 1366×768、1920×1080、窄屏；键盘焦点与 MapLibre CDN 不可用的错误文案。
9. 原 `/`、`/workbench`、旧地图服务及历史数据继续可用。
