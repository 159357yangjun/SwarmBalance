## 硬阻塞（不加 z 就无法工作，或加了会静默错）

### H1 障碍相交本质是二维 ⛑（部分）
- `frontend/environment.py:2008` `line = LineString([pos1, pos2])`
- `frontend/environment.py:2015` `if geom.intersects(line):`
- `frontend/environment.py:2013` bbox 四轴比较（`bxmax < lminx or … bymin > lmaxy`）
- `frontend/no_fly_zone.py:50-51` `contains(x, y) → geometry.contains(Point(x, y))`
- `frontend/no_fly_zone.py:53-58` `intersects_line` + `intersection(line).length > 0.1`（"擦角忽略"阈值基于平面交线长度）
- `frontend/no_fly_zone.py:159` 圆形禁飞区 `Point(cx, cy).buffer(r)`
- `console/server.py:751` 机巢落楼校验 `buffer(1.0).contains(Point(x, y))`

shapely 无原生体素求交 ⇒ 必须换 3D 基元，或改成"分层 2D"。
**注意**：`environment.py:176-177` 注释自称 bbox 剔除是"等价优化"，该论证仅在二维成立。

### H2 A* 的整个度量空间就是那个二维距离 ⛑
`heuristic`（`:1947-1951`，纯 `sqrt((p1[0]-p2[0])**2 + (p1[1]-p2[1])**2)`）同时承担四职：
`:1910` f 初始化、`:1918` **终止判据**（`< 1` 即到达）、`:1933` **边权 g 增量**、`:1938` f 合成。
加上节点被 `round_pos`（`:1871-1872`）压成二元组、由 `set()`（`:1901`）去重 ⇒ **加 z 等于换图**，
不是"多一维坐标"。改一处即改变路径本身，而非只改变搜索顺序。

### H3 航点元组第 3 槽已被 type 占用 ⛑（实测 7 处，全在 environment.py）
```
:x998  :1000  :1144  :1156  :1542  :1703  :1705
   if len(wp) >= 3 and wp[2] in ('source','dest') / popped[2] == …
```
z 只能进第 4 槽 ⇒ 这 7 处判断 + 相关解包点必须同批改，否则**静默错乱而非报错**。
（纠正审计员的一处说法：`frontend/drone.py` 里这类索引判断实测 **0 处**，它有的是
`target_x, target_y, _ = target` 形式的解包分支 `:302-304`。）

### H4 坐标用元组全等判定 ⛑
- `frontend/drone.py:291` `if (self.x, self.y) == nest_pos:` （另见 `:331`、`:345` 同类）
- `frontend/environment.py:600` `math.dist(last_pos, target_pos) < 1e-6`

二元组 vs 三元组恒 False ⇒ 泊位登记/换电改道会**静默不走**，不抛异常。

### H5 GeoJSON 主动降维
`frontend/data_source.py:376-386` `tuple(coords[0][:2])`、`coords[0][0][:2]` ——
3D 坐标里的 z 被切片直接丢弃且不报错。

### H6 SLA/deadline 由平面距离决定（业务口径，非显示问题）
`frontend/task.py:543` `math.hypot(destination[0]-source[0], destination[1]-source[1])`
→ `_sla_seconds()`（`:520-527`）⇒ 上 z 后若不补垂直段，deadline 系统性偏松。

### H7 高度值在过滤后即丢弃（当前真实语义）⛑
`frontend/environment.py:174` 筛 `height > 20` → `:178` 重塑为 `(geometry.bounds, geometry)`，
height 键消失。⇒ **>20 m 整条垂直射线不可穿；≤20 m 无论 19 m 还是 3 m 完全透明。**

## 结论（已由用户裁定顺序，本轮不执行）

1. 2.5D 不是"给现有对象加一个字段"：**H1/H2/H3 三处都是本质性改动**，其中 H2 会让既有全部
   路径规划结果失去可比性 ⇒ 必须先有 Gate A 式等价基线，再动。
2. 把 **height 接进相交判定**（H7）方向认可，但**明确不在当前做**：那等于继续往 2000+ 行的
   `Environment` 里加模型逻辑，与本轮"削弱 God Object"的目标相反。它排在 RoutePlanner 抽离
   与成本口径统一之后。
3. 任何 2.5D 改动都必须与总纲 §5.4 的 Gate B（默认零漂移）配合：先证明关掉 z 通道时 KPI 逐值不变。

### 冻结的执行顺序（覆盖此前所有版本）

```
Q1 + Q2 + Q3 审计闭环
→ RoutePlanner 从 Environment 抽离
→ 新旧 A* 行为等价门（Gate A）
→ 统一 Scheduler 预测成本与实际 Route 成本
→ height-aware 2.5D
→ 真正的 z / 3D
```

当前禁止提前做的事：改 height 行为、加 z、改 waypoint 结构、重写 A*、做轨迹平滑、接 ROS2/Gazebo。

### Waypoint 数据结构（裁定：不扩裸 tuple，改统一对象）

现状 `(x, y, type)` 的第 3 槽已被 `'source'/'dest'/'waypoint'` 占用，且读取方靠
`len(wp) >= 3 and wp[2] == …` 判语义（实测 7 处，全在 `frontend/environment.py`）。
因此 z **不能**简单追加成第四元 —— 裸 tuple 每加一维都要重排全部解包点，属于静默错误温床。

建议（Phase 1 只定义，不迁移调用点）：

```python
@dataclass(frozen=True)
class Waypoint:
    x: float
    y: float
    z: float = 0.0          # Phase 4 前恒为 0；有名字就不会和 role 抢位置
    role: str = "waypoint"  # source | dest | waypoint | corridor
    task_id: str | None = None   # 现由外部并行数组推断，归属后自描述
```

配套约束：① 迁移期两种形状并存，由单一适配层转换，禁止各处自行 `wp[2]`；
② `len(wp) >= 3` 这类判断必须整体消失，改由 `role` 显式判定；
③ 元组全等判据（H4：`drone.py:291/331/345`）改为带容差的坐标比较或 id 比较，
   并纳入 2.5D 迁移门 —— 因为二元组 vs 三元组的 `==` 恒 False，不会报错只会静默失效。
