# SwarmBalance v0.7：演示场景、运行态快照与态势趋势

v0.7 的目标不是增加新的调度算法，而是解决三个实际问题：

1. **答辩前不用每次手工调一堆参数**；
2. **演示到关键节点时可以保存并反复回放**；
3. **刷新浏览器或切换页面后，实时趋势不再从零开始**。

所有演示动作仍调用当前项目里的真实 `Environment` 与 Greedy / GA / PSO / OR-Tools 调度器，不存在“演示专用假算法”。

## 1. 一键答辩场景

Web 控制台“指标”页顶部新增 **答辩演示场景**。当前内置四套：

| 场景 | 推荐算法 | 重点展示 |
|---|---|---|
| 应急医疗高峰 | GA | 异构能力匹配、P3 紧急插单、任务链滚动重调度 |
| 机巢拥堵与优先级仲裁 | GA | 单泊位压力、换电排队、动态优先级仲裁 |
| 故障韧性与局部重规划 | GA | 无人机故障回收任务、机巢关闭、任务重新分配与改道 |
| 标准综合演示 | GA | 普通订单流、异构机队分工、紧急插单 |

加载场景后系统会：

- 对 `config/simulation.json` 做可逆 patch；
- 热重建环境；
- 自动切换到该场景推荐的算法与固定 Seed；
- 按需要暂停/恢复自动任务流；
- 注入少量预设人工任务；
- 显示“下一幕”剧本按钮。

首次进入演示模式时，系统会在服务端保存一份**进入演示前的配置与算法/Seed**。点击“恢复演示前配置”即可还原。

> 演示场景会改变主 `simulation.json`，但修改是可逆的。和批量实验不同，批量实验仍使用隔离配置副本，不碰主配置。

## 2. “下一幕”不是假播放

每个预设包含一条简短剧本，例如“应急医疗高峰”：

1. 执行首轮 GA 分配；
2. 运行中插入新的 P3 急救任务；
3. 单步触发真实滚动重调度；
4. 推进若干步观察任务链、换电与任务状态。

“机巢拥堵”会真实调用人工补能接口，让多架无人机进入现有泊位仲裁；“故障韧性”会真实调用无人机停飞和机巢关闭接口。

因此答辩时可以直接说明：

> 演示剧本只把多次人工点击自动化，每一步仍然走系统公开控制接口和真实调度算法。

## 3. 运行态快照

“指标”页新增 **运行态快照**。

可以在任意运行时刻保存，例如：

- `紧急插单前`
- `故障注入前`
- `机巢拥堵形成`
- `GA分配完成`

快照会保存当前服务进程中的动态状态，包括：

- 仿真时间与 step；
- 无人机位置、电量、载重、航线、故障/换电状态；
- 机巢占用、关闭状态与排队；
- 待调度、已分配、完成任务；
- 调度器运行缓存；
- observation；
- Python `random` 与 NumPy 全局随机数状态（保证 TaskGenerator / Greedy / PSO 从恢复节点继续时复用同一段随机序列）；
- 调度事件；
- 历史轨迹；
- 统计趋势；
- 当前演示剧本光标。

为了避免复制体积很大的 OSM 建筑几何，静态地图本身不重复保存。结构性场景编辑会改变机队/机巢/禁飞区，因此快照带一个「环境代」指纹：跨代恢复会被**拒绝并给出可执行的提示**，而不是悄悄恢复到不兼容的结构上。热重建**不再清空**已存的快照（早先的行为是清空，会让用户误点一次「保存并应用」就丢掉答辩前存的关键节点，且无法撤销）。界面会显示「已用 N / 5」，槽位满时淘汰最旧的一个并给出提示。

当前最多保留 5 个内存快照，同名保存会覆盖。快照只在当前 `python -m console.run` 服务进程中有效，重启服务后不会保留。

## 4. 实时运行态势

指标页新增“运行态势”提示，自动汇总：

- P3 待调度任务数量；
- 泊位排队数量；
- 停飞无人机数量；
- 关闭机巢数量；
- 低电无人机数量；
- 当前在线无人机数量。

状态分为：

- **平稳**：无明显异常；
- **关注**：存在紧急积压、排队、低电或资源故障；
- **严重**：没有可用无人机等系统级问题。

这只是运行态势摘要，不替代具体算法指标。

## 5. 趋势图改造

完成率趋势升级为 **关键指标趋势**，由服务端每 5 步采样并保存最近 360 个点：

- 完成率；
- 超时率；
- 机队利用率；
- 待调度任务数。

这样浏览器刷新后趋势仍能从服务端恢复，而不是只依赖浏览器内存。

## 6. 推荐答辩操作

一个稳定的 4~6 分钟演示可以这样做：

1. 加载“应急医疗高峰”；
2. 保存快照 `紧急插单前`；
3. 点“执行下一幕”完成首轮分配；
4. 再点一次插入 P3 急救任务；
5. 点任务查看候选无人机解释，然后执行下一幕触发真实 GA 重调度；
6. 恢复 `紧急插单前`，证明同一节点可重复演示；
7. 切换“故障韧性与局部重规划”，按剧本制造无人机故障和机巢关闭；
8. 最后进入“实验”页展示一键结项实验与统计结果。

这样可以同时说明：**系统能自由交互、算法能动态调度、场景能复现、结果能实验验证。**
