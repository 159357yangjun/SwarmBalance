## 1. P_seq 的形式化定义（冻结候选）

**输入（全部来自单次 `optimize()` 快照，即 L1 静态实例）**
- `T` 任务：`s_i`(取货点)、`d_i`(送达点)、`w_i`、`v_i`、`dl_i ∈ ℝ∪{∞}`；
- `J` 机：`p_j`(当前位置)、`r_j`(就绪时刻)、`sp_j`、`cap_j`、`B_j`(容量)、`b_j`(当前电量)、`e_j`(Wh/m)、`λ_j`、`is_charging_j`；
- 全局：`W_max=30`、`ρ=0.1`、`τ_swap=180`、`tol=600`、`K_max=3`、低电阈值 `θ=0.2`、站点集 `S`；
- 权重：`w_makespan=1`、`w_tardy=2.0`、`w_dist=0.01`、`w_unass=1e4`、`w_match=80`、`w_new_chain=−30`。

**决策对象**：每机一个**有序序列** `π_j`，两两不相交；`U = T \ ⋃_j π_j` 为弃单集。

**状态递推**（严格照抄 `try_append`，不重新发明）：对 `π_j` 逐任务推进 `(pos, t, load, battery)`，
每步先判低电换电（`battery/B_j < θ` 且有站点 ⇒ 飞最近站、置满、耗时 `dist/sp + τ_swap`，`:177-191`），
再算 `d_1=dist(pos,s_i)`、`d_2=dist(s_i,d_i)`，能耗
`E = e_j·d_1·(1+λ_j·load/cap_j) + e_j·d_2·(1+λ_j·(load+w_i)/cap_j)`（`chain_codec.py:194-195`）。

**硬约束（P_seq 成员资格，逐条有正反例）**
| 编号 | 谓词 | 出处 |
|---|---|---|
| H1 | `∀j, |π_j| ≤ K_max` | `:159`（局部搜索同受此约束 `:350`） |
| H2 | 链上任意前缀累计 `Σ w ≤ min(cap_j, W_max)` | `:129-131 can_carry` + `environment.py:1065-1067` |
| H3 | 挂载前 `battery − E ≥ B_j·ρ` | `:196-197` |
| H4 | `tardiness_i = max(0, C_i − dl_i) ≤ tol`（`dl_i=∞` 豁免） | `:204-206` |
| ~~H5~~ | ~~机巢泊位并发~~ | **已剔除**（C1） |

**目标函数**（最小化）：
```
J(π,U) = makespan + w_tardy·Σ_i tardiness_i + w_dist·Σ_j dist_j
         + w_unass·|U| − w_match·Σ_{i∈⋃π} match(i)
```
`match ∈ [0,1]`（`matching.py:51-67`，内部权重 `load .4 / speed .3 / range .3`）。

**⚠ 语义忠实性的一条硬要求（你第 4 条最后那句）**：GA 的**解码本身是贪婪的**
（`greedy_split_decode:398-410` 逐个任务选"当前增量代价最小"的机），`improve_chains` 只做 swap/2-opt/relocate。
⇒ GA 求的不是"全域最优"，而是这个贪婪+局部搜索邻域内的解。**Oracle 必须在同一个可行集上比**：
P_seq 的可行集 = 满足 H1–H4 的 (π, U) 全体，**不含**任何额外限制；
Oracle 给的是该集合上的真最优，GA 与之的差 = **算法间隙 + 建模间隙**，两者要在报告里分开说（§5）。

## 2. Oracle 建模方案（两条独立路径，互核）

| 路径 | 做法 | 角色 |
|---|---|---|
| **O1 穷举** | 枚举 `(J+1)^|T| × |T|!`（每任务：给某机 or 弃单 × 全局顺序），逐候选用**独立实现的可行性判定**过滤后取最小 J | 小规模的**真最优**，且是 O2 的裁判 |
| **O2 CP-SAT 新模型** | 独立新建，**不复用** `ortools_scheduler.py` 的任何代码；链式 + 时间窗 + 能量累加 | 中等规模的最优/上下界 |

不 import `frontend/`、不改 `ga_scheduler/pso_scheduler/ortools_scheduler/greedy/scheduler` 任何一行；

## 4. 最优性 gap 定义（含符号问题，实测支撑）

设 `c_alg` = 算法解的目标值，`c_opt` = Oracle 值（或下界 `LB`）。

1. **主口径：绝对间隙** `Δ = c_alg − c_opt`，单位=等效秒，恒非负（因为 Oracle 在同可行集上最小）。
   **报告必附各分项贡献**（makespan/tardiness/dist/unassigned/match 五项各自的加权值），否则 Δ 无法解释。
2. **相对口径仅在 `c_opt > ε` 时启用**：`gap% = Δ / c_opt`，`ε` 待定但必须显式写出并说明理由。
   实测依据：`c_opt = 0` 时该式抛 `ZeroDivisionError`；`c_opt < 0` 时 `Δ/c_opt` **符号翻转**
   （构造例：`c_opt=−100, c_alg=−50 ⇒ −0.5`，看起来像"比最优还好"）。
3. **只有下界时**（O2 未证最优）：报 `Δ ∈ [c_alg − UB?, …]` 形式的区间，或直接印
   `status=FEASIBLE, best_bound=…` ⇒ **标注"最优性未知"**，禁止把 FEASIBLE 解当最优解算 gap。
4. 目标值符号要**逐实例打印**，不许汇总成一个平均数掩盖个别实例的非正最优。

## 5. 三层实验协议（A/B/C，你的第 5 条）

| 实验 | 比较对象 | 允许的主张 | **禁止**的主张 |
|---|---|---|---|
| **A：P_seq 最优性** | GA vs Oracle(O1/O2) | 同题条件下的 `Δ`、gap%、可行性违规数 | — |
| **B：P_assign 最优性** | OR-Tools vs 分配型精确基准 | 同题条件下的 gap | 把 A 的结论套到 B |
| **C：统一运营评价** | 四算法同场景端到端 | 完成率/超时率/能耗/可行性的**策略表现差异** | **称其为"最优性差距"** |

**PSO 归类待确认（你第 1 条）**：PSO 是偏好矩阵 `argmax` 分配（`pso_scheduler.py:542`），
但其 fitness 是 `on_time/delay/energy` 三项归一化加权，**与 P_assign 的目标（makespan+tardiness）不同**，
且其解码不校验 H3 电量。⇒ **PSO 目前不属于任一问题的忠实求解者**，
只能：① 在 C 类里作为策略评；② 或在 B 类里以"其分配结果被 P_assign 目标重新打分"的方式评，
且必须写明这是**重新赋义**，不是它自己的优化目标。这条我不自行归类，留给你裁定。

**介入次数纪律**：A/B/C 每格都印 `optimize_calls`；`calls=0` ⇒ 记作 fallback 性能，不得记作算法性能
（出厂默认是轻载，PSO/GA/OR-Tools 全 0 次 ⇒ **基准实验必须重载工况**，阈值 15 不动）。

| G5 gap 符号安全 | 每格打印 `c_opt` 符号；`c_opt ≤ ε` 的格子禁用 gap%，只报 Δ | 出现"比最优还好 50%"这类假读数 |
| G6 分母在场 | 每格打印 `optimize_calls`、批次任务数、机队数 | 无分母结论（Phase 0 教训） |
| G7 最优性诚实 | `status≠OPTIMAL` 的格子必须印 `best_bound` 且文字标"最优性未知" | 把可行解当最优解 |

G4 是本设计的承重墙：**它检验的不是"算得对不对"，而是"Oracle 和 GA 说的是不是同一门数学"**。
建议实现顺序也按 G4 先行——先用现有 GA 产出的解做逐位对账，红了就先修定义，别急着跑大规模。
