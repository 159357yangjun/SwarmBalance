# 群智优衡 v0.5：场景事件与韧性演示

## 1. 功能定位

v0.5 在自由仿真主系统中加入“运行时场景事件”，用来演示调度系统面对资源临时失效时如何继续工作，而不是把事故做成单独的离线算法脚本。

支持两类事件：

- **无人机故障停飞 / 恢复上线**；
- **机巢临时关闭 / 重新开放**。

事件不会重置仿真，不会改写 `simulation.json`，会直接作用于当前时刻的无人机、电量、任务链和机巢队列。

## 2. 无人机故障

在 2D / 3D 地图点击任意无人机，详情面板可执行“模拟故障停飞”。“调度”页也可随机挑选一架在线无人机制造故障，优先选择正在配送的无人机，以便观察任务回收和重分配。

故障发生后：

1. 无人机立即冻结当前位置，不继续移动；
2. 不再参与新的任务分配；
3. 若正在占用换电泊位，立即释放资源；
4. 未完成任务回到待调度池；
5. 调度器运行时缓存重新初始化，但物理仿真状态不重置；
6. 下一次“单步/播放”时，当前所选算法重新处理这些任务。

### 简化口径

当前模型把故障机上的未完成任务**回滚到原任务起点**重新入池，用于稳定、可复现地观察重新调度。暂不模拟无人机在空中故障后的货物交接、迫降点和救援转运。

## 3. 机巢临时关闭

点击机巢可执行“临时关闭机巢”，调度页也提供“随机关闭机巢”。

采用**软关闭**：

- 不再接受新的泊位 / 换电请求；
- 已经开始换电的无人机正常完成当前服务；
- 已在该站等待的无人机改道到最近开放机巢；
- 正在飞往该站补能的无人机会更新目的地；
- 至少保留一个开放机巢，系统不允许关闭最后一个可用站点。

## 4. 推荐答辩演示

建议用 GA，Seed=100：

1. 重置并播放约几十步，让多架无人机进入配送状态；
2. 暂停，在“调度 → 场景事件注入”点击“随机无人机故障”；
3. 查看事件日志：`故障停飞 → 任务回收到待调度池`；
4. 查看待调度任务与候选无人机解释；
5. 单步，观察真实 GA 将任务重新放入其它无人机任务链；
6. 再点击“随机关闭机巢”，观察机巢变灰 / 打叉以及补能改道日志；
7. 恢复播放，看系统继续运行；
8. 点击“恢复全部”，演示资源恢复；
9. 最后进入“实验”页说明批量实验与自由仿真共用同一调度/环境实现。

这段演示表达的是“**滚动时域调度 + 资源状态变化下的局部重规划**”，不要把它描述成申请书未承诺的“容错飞控”或“真实故障诊断”。

## 5. API

```text
POST /api/drones/{drone_id}/incident
{"out_of_service": true, "reason": "模拟通信故障"}

POST /api/drones/{drone_id}/incident
{"out_of_service": false, "reason": "恢复"}

POST /api/nests/{station_id}/incident
{"closed": true, "reason": "模拟维护"}

POST /api/nests/{station_id}/incident
{"closed": false, "reason": "恢复"}
```

## 6. 快速测试

```bash
python -m unittest \
  console.test_environment_incidents \
  console.test_command_console \
  experiments.test_runner -v
```

事故测试不加载真实 OSM，因此即使当前机器没有 `osmnx` / `pygame` 也可以验证核心状态迁移。
