# SwarmBalance v1.0 结项最终验收清单

这份清单用于**冻结功能后的最后验收**。它不是功能规划书，而是提交/答辩前必须逐项确认的门槛。

## 1. 正式运行环境

- [ ] 使用 Python 3.10。
- [ ] `python release_check.py --strict` 全部通过。
- [ ] OSMnx / OR-Tools / FastAPI / pygame 均按 `requirements.txt` 安装。
- [ ] `python -m console.run` 能打开 Web 控制台，不使用 `--portable` 生成正式实验数据。

## 2. 交互式系统验收

- [ ] 播放 / 暂停 / 单步 / 倍速可用。
- [ ] 运行中插入 P3 紧急任务后，下一步真实触发当前算法重调度。
- [ ] 点击无人机、任务、机巢能看到状态、任务链、候选解释、排队信息。
- [ ] 无人机故障后未完成任务回收并可重新分配。
- [ ] 机巢关闭后新补能请求能改道，且不能关闭最后一个开放机巢。
- [ ] 场景编辑、场景库、运行态快照按说明工作。

## 3. 正式实验验收

- [ ] `python run_conclusion.py --preset conclusion` 完整结束，无失败运行。
- [ ] `raw_runs.csv` 保留每个 Seed 的原始结果。
- [ ] `algorithm_comparison.csv` 与敏感性 CSV 已生成。
- [ ] `algorithm_comparison_stats.csv` 包含均值、标准差和中位数。
- [ ] `paired_ga_vs_greedy.csv` 只用于相同 Seed 的描述性配对比较，不写成“显著性检验”。
- [ ] `reproducibility.json` 已生成，并记录正式环境、输入文件哈希和关键依赖版本。
- [ ] 图表与结项报告引用的是同一个实验目录，不能混用历史 CSV。

## 4. 结项口径验收

- [ ] 项目核心仍表述为“异构能力匹配 + GA 任务链优化 + 机巢动态资源调度”。
- [ ] Greedy / OR-Tools 是基线；PSO / MARL 是扩展比较。
- [ ] 不声称 GA 保证全局最优。
- [ ] 不把调度层故障注入描述为真实飞控故障诊断。
- [ ] 不把便携 OSM 回退模式的数据用于正式论文结论。
- [ ] 若实验结果没有支持“GA 优于某算法”，报告中如实写结果，不倒推结论。

## 5. 一键最终流水线

Windows 正式机器可运行：

```bat
finalize_project.bat
```

它会依次执行：

1. `release_check.py --strict`
2. `run_conclusion.py --preset conclusion`
3. `build_conclusion_package.py`

最终的证据归档包位于 `deliverables/`。
