## 3. 拿到这些数据后，"完整数据集"应该长这样（目标 schema）

每个机型一行、每个参数一列，**六列必填**，缺一列就不算已溯源：

```
parameter | value | unit | source_url | test_condition | evidence_type | error_range
```

`evidence_type` 只允许三个取值：`measured`（实测）/ `manufacturer`（厂商铭牌）/ `derived`（由前两者算出，附算式）。
**不允许第四种**——现在的 0.032/0.06/0.142 三个能耗系数在这套 schema 下会全部落在"填不出 source_url"，
即当场暴露，而不是像现在这样混在配置里。

分层覆盖度目标（现状 → 目标）：

| 层 | 现状 | 目标 |
|---|---|---|
| L1 几何 | OSM 真数据 ✓ | 保持；建筑高度缺失要标 `derived` 并给 fallback 说明 |
| L2 铭牌 | FlyCart 全 A；ARK40 **本轮补齐 12 项 A**；美团仅 B | 三机型各 ≥6 项 A/B，其余标 missing |
| L3 能耗 | C（除 heavy_cargo 可派生 0.248 Wh/m） | 至少一个机型有 `measured` 拟合曲线 + 留出集误差 |
| L4 天气 | **E1 已接入风能耗**（情景常量，K 为 assumption）；逐小时 CSV 未接 | ERA5 区域风况（标 coarse）；措辞用"风环境情景"，**不声称代表某巡航高度** |
| L5 高程 | **模型无高度状态**（非"固定 60 m"） | 若要真三维需先引入 z/垂直速度/阶段机＝模型重定义；在此之前 DEM 与楼高均不影响调度结果 |
| L6 需求 | 合成（seed 已登记） | 保持合成，但 UI 与文档**必须显式标"合成需求"** |

## 4. 下一步（等你点头才做）

1. **取 CMU CSV**：KiltHub 走浏览器通道（我这侧 403），或由你从学校网络下载后放进 `data/raw/`；
   到手后按"整次飞行划分"拟合 hover/cruise/climb 分项功率，报告留出集的总耗能 MAPE。
2. **改标定**：`heavy_cargo` 用派生 0.248 Wh/m（现为 0.142，偏低 1.7 倍）；
   `standard_cargo` 待电池容量出处；`light_express` 待厂商数据 ⇒ 先按"派生 + 标注"处理。
3. **重跑结项**：这会推翻答辩页现有读数，所以单独等你批准。
4. 若暂时拿不到 CSV：**把三个系数在配置里就地标注 `evidence_type: derived/none`**，
   并让 `/api/meta` 与前端铭牌面板显示"该参数为估算值"——这是世界逻辑规格书缺口 E（真实性在 UI 不可见）的正解。
