# 群智优衡 · 仿真软件设计规范

**Simulation Software Design Specification**
版本 v1.0 ｜ 适用范围：城市应急与低空物流无人机集群调度仿真平台 ｜ 性质：规范性（Normative）

> 本规范是项目**世界逻辑与软件设计的唯一权威事实源（single source of truth）**，同时作为项目**主要展示对象**：阅读本文件即可理解"这套仿真世界如何运转、软件如何分层、工程上如何保证正确与可复现"。
> 术语关键字：**必须 / MUST**（强制）、**应当 / SHOULD**（推荐）、**禁止 / MUST NOT**（严禁）、**可 / MAY**（可选）。

---

## 第 0 章 总则与设计哲学

### 0.1 核心命题
**仿真软件 ≠ 看起来像的视频。仿真软件 = 维护一套独立的世界状态，内核驱动状态变化，渲染仅把状态画出来。**

### 0.2 三条不可动摇的公理
- **P1（状态优先）**：世界状态是唯一真相；画面只是它的一种输出。
- **P2（渲染单向）**：渲染**禁止**反向修改世界状态；渲染结果**禁止**作为仿真逻辑输入。
- **P3（确定性）**：相同初始条件 + 相同种子 → 每次运行得到**逐拍一致**的结果。

### 0.3 四层职责
仿真内核（纯逻辑）→ 场景管理（状态容器/快照）→ 渲染（只读视图）→ 交互（改状态而非改像素）。

## 第 1 章 世界逻辑规范（WL）

### WL-1 时空基准
- **WL-1.1** 坐标系**必须**为本地投影米制平面坐标（OSM 导出），单位米。示例 `(357600, 3462308)`。
- **WL-1.2** 时间**必须**以离散步（step）推进，且 **1 step = 1 秒**（`STEP_SECONDS = 1.0`）。该映射**必须**在代码常量与 UI 中显式声明，禁止仅靠配置"凑出自洽"。
- **WL-1.3** 单局时长 `episode_max_steps = 3600` → 1 小时仿真。
- **WL-1.4** 全系统**必须**统一单位：距离 m、速度 m/s、时间 s、质量 kg、电量 Wh。**禁止**混用米/厘米或秒/步。

### WL-2 实体规范
#### WL-2.1 无人机（真实机型锚定）
无人机**必须**以真实公开机型参数建模，**禁止**使用无来源的魔法数：

| 类型 | 参考机型 | 速度 m/s | 载重 kg | 电池 Wh | 能耗 Wh/m | 满载航程 km |
|---|---|---|---|---|---|---|
| light_express 轻载快递 | 美团第四代配送无人机 | 20.0 | 2.4 | 380.0 | 0.032 | 10 |
| standard_cargo 标准货运 | 顺丰丰翼方舟 ARK40 | 14.0 | 10.0 | 1600.0 | 0.06 | 20 |
| heavy_cargo 重载运输 | 大疆 FlyCart 30 双电 | 20.0 | 30.0 | 3968.8 | 0.142 | 16 |

- **WL-2.1.1** 运动学：每步沿航线航点直线位移 `speed × STEP_SECONDS` 米。
- **WL-2.1.2** 能耗：`消耗 = 距离 × 基础能耗 × (1 + 载重比 × 载重惩罚系数)`；到点即扣电。
- **WL-2.1.3** 低电处置：电量比低于阈值**必须**触发预判式改道换电；任务链放行**必须**保留电量储备（默认 15%）。

#### WL-2.2 机巢（换电站）
- **WL-2.2.1** 默认 5 站，换电耗时 180 s；泊位有限（默认 2）。
- **WL-2.2.2** 泊位竞争**必须**用动态优先级仲裁（因素：电量紧迫度、等待时长、任务紧迫度），并提供 FIFO 作为对照策略。
- **WL-2.2.3** **禁止**关闭最后一个可用机巢。

#### WL-2.3 任务 / 需求
- **WL-2.3.1** 每个任务**必须**携带：重量、取货点、送达点、生成时刻、优先级（1–3）、类别（urgent/emergency/bulk/normal）、截止时刻、状态。
- **WL-2.3.2** 截止时刻**必须**基于可解释 SLA 基线：`deadline = 生成时刻 + random(900, 3600)s`，参考速度 14 m/s、基础 420 s、每 kg +24 s。

#### WL-2.4 禁飞区
- **WL-2.4.1** 禁飞区为飞行硬约束，**必须**参与路径规划与可行性判定；穿越**必须**触发绕飞，并计数 `no_fly_detours`。
- **WL-2.4.2** 任务起点/终点落在禁飞区内**必须**被拒绝。

### WL-3 单步推进规范
`step(actions)` 每次调用**必须**依次完成：
1. 将 `{drone_idx: [task_id,...]}` 分配为航线；支持同源追加与异源"顺路接入"任务链（上限 3 段、绕飞阈值 1500 m）。
2. `current_time += 1`（秒）。
3. 按需生成新任务（交互式控制台**可**暂停自动订单流）。
4. 各无人机 `update()`：沿航点运动、扣电、到点取/送货、低电改道换电。
5. 统计：里程（区分空载/载货）、能耗、机队利用率、任务完成（航点弹出判定）。
6. 返回 observation / reward / done / info。

### WL-4 需求生成规范（现实锚定，**禁止**均匀乱撒）
- **WL-4.1** 取送点**必须**以**热点聚类**生成：默认 60% 概率落在热点中心（医院/商圈）半径 80 m 内。
- **WL-4.2** 到达**必须**呈**高峰/平峰潮汐**：peak 20 步/单、平峰 45 步/单，peak 概率 0.7，周期 1200 步。
- **WL-4.3** 重量**必须**按分档抽样，且分档**必须**对应真实物流品类：
  - 1–2 kg（55%，外卖/小件，美团轻载）
  - 3–10 kg（35%，标准快递，顺丰 ARK40）
  - 11–25 kg（10%，重货/应急，大疆 FlyCart 30）
- **WL-4.4** 单局默认 60 单、初始 12 单。

### WL-5 环境与约束
- **WL-5.1** 建筑/路网**必须**来自真实 OSM 数据（当前为杨浦区局部）。
- **WL-5.2** 场景**应当**支持环境事件（插单、改优先级、故障停飞、关闭机巢、风场/天气——后者为规划项）。

### WL-6 指标口径
- **WL-6.1** **必须**至少统计：完成率、准时率、加权延迟、生成→送达时长、超时率、总能耗(Wh)、空载/载货里程、机队利用率、顺路接入次数、禁飞绕飞次数、泊位利用率、排队等待。
- **WL-6.2** 所有指标**必须**机械可复算（同一快照 → 同一指标值）。

## 第 2 章 软件架构规范（SA）

### SA-1 分层
系统**必须**分为五层，依赖**只能自上而下**：

```
UI/交互层 ──命令──▶ 渲染层(只读) ◀──快照── 场景管理/世界状态 ◀── 仿真时钟 ◀── 仿真内核 ◀── 领域实体
```

**禁止**跨层反向依赖；**禁止**仿真内核 import 任何渲染库或 Web 框架。

### SA-2 仿真内核（Simulation Core）
- **SA-2.1** **必须**为纯逻辑、无 UI、无渲染、无网络；可在无显示环境下直接运行。
- **SA-2.2** **必须**可独立单元测试（不启动窗口、不依赖图形库）。
- **SA-2.3** 输入初始参数 + 逐步 actions，输出每一时刻世界状态。
- **SA-2.4** 职责切分（由现有 `Environment` 上帝类拆分而来）：运动学 / 需求生成 / 机巢仲裁 / 路径规划 / 避障 / 随机源。

### SA-3 场景管理 / 世界状态（Scene Manager）
- **SA-3.1** **必须**有单一 `WorldState` 容器，集中全部实体 + 仿真时钟 + 随机源状态 + 指标。
- **SA-3.2** **必须**提供实体注册表的增删查（按 id）。
- **SA-3.3** **必须**提供整世界状态的序列化/反序列化（快照）与 `hash_state()`。
- **SA-3.4** **必须**提供检查点保存/恢复与步历史（回放）。

### SA-4 仿真时钟（Simulation Clock）
- **SA-4.1** **必须**采用**固定时间步**推进，物理步长与渲染帧率**解耦**。
- **SA-4.2** 服务端**应当**以固定速率时钟推进内核；客户端**应当**在相邻两次快照间插值渲染（画面卡时物理不变慢、结果不变）。
- **SA-4.3** **禁止**把物理计算放在渲染循环内。

### SA-5 渲染层契约
- **SA-5.1** 渲染**必须**只读：从世界状态/快照构建绘制视图，**禁止**回写状态。
- **SA-5.2** **可见性是渲染属性，不是存在属性**：被遮挡/不可见**禁止**导致实体从场景中删除。
- **SA-5.3** **禁止**依赖渲染结果（裁剪、遮挡、透明度）做仿真判定；遮挡判断属于视图/业务层。
- **SA-5.4** 可视化仅保留 Web（three.js）单一实现，且**必须**只消费服务端快照 JSON；桌面 pygame 渲染器已于 v1.0.1 移出产品范围，仿真内核与后端**不得**为可视化引入 GUI 依赖。

### SA-6 交互层契约
- **SA-6.1** 所有交互（插单、改优先级、故障、关机巢、暂停订单流）**必须**通过命令修改世界状态，**禁止**直接改渲染画面。
- **SA-6.2** 非法命令**必须**被拒绝且整体回滚，世界状态保持不变。

## 第 3 章 仿真工程准则（SE）

### SE-1 时间步长
- **SE-1.1** 采用固定时间步（推荐），**禁止**使用跟随帧率的可变步长。
- **SE-1.2** 仿真逻辑与渲染逻辑**必须**分离，运行于不同循环/线程。

### SE-2 状态与对象管理
- **SE-2.1** 每个物体**必须**有独立状态存储（id、位置、速度、质量 + 业务标签）。
- **SE-2.2** 属性**必须**分类：物理属性（位置/速度/质量）、渲染属性（颜色/可见性/纹理）、业务属性（id/标签）。
- **SE-2.3** 物体销毁**必须**显式调用；**禁止**以"关掉渲染"等同于"消失"。

### SE-3 渲染层陷阱
- **SE-3.1** 渲染画面**禁止**反向影响世界状态。
- **SE-3.2** 遮挡**必须**用业务层标记或射线**查询**实现；射线**只查询，不改变世界**。

### SE-4 确定性
- **SE-4.1** 所有随机**必须**走集中式、可种子化的随机源。
- **SE-4.2** 核心仿真**必须**单线程；**禁止**让线程调度不确定性破坏确定性。
- **SE-4.3** **必须**支持保存整场景快照并加载回到过去某一刻；**快照只保存世界状态，不保存画面**。

### SE-5 数值稳定与边界
- **SE-5.1** 位置**必须**有边界守卫（越界 clamp 并标记）；**必须**有 NaN/数值爆炸兜底。
- **SE-5.2** **应当**有"卡死/无进展"检测（连续 N 步未移动且无任务 → 标记，不静默）。

### SE-6 单位
- **SE-6.1** 全系统统一单位，见 WL-1.4。

### SE-7 序列化与回放
- **SE-7.1** **必须**支持场景保存/加载；浮点序列化注意精度。
- **SE-7.2** 回放**可**用两种方式：实时重仿真 或 状态序列回放（当前实现为后者）。

### SE-8 测试
- **SE-8.1** **禁止**仅靠肉眼判断仿真对错；**必须**有自动化测试直接读内核数据做断言。
- **SE-8.2** **必须**覆盖：确定性（同种子逐拍一致、快照往返一致）、遮挡不变量（遮挡不删实体不改状态）、越界守卫、非法命令回滚。
- **SE-8.3** 单元测试**禁止**依赖渲染。

### SE-9 依赖与物理引擎选型
- **SE-9.1** **明确决策：本项目不引入 PyBullet / Bullet3 / ODE 等刚体物理引擎。** 理由：这是运动学调度-优化仿真（航线预规划 + 规划期绕障），非刚体动力学；引引擎只增依赖与不确定性而无法建模真实问题。
- **SE-9.2** 若未来需风场扰动/悬停-巡航能耗差，**应当**在核内用**确定性解析公式**实现，仍不上引擎。

## 附录 A · 术语
- **世界状态（World State）**：一切仿真对象的当前数值集合，渲染的唯一输入。
- **快照（Snapshot）**：世界状态在某一时刻的完整序列化。
- **固定时间步（Fixed Timestep）**：以恒定步长推进仿真，与渲染帧率无关。
- **CCD（连续碰撞检测）**：避免高速物体隧穿的检测方式（本项目因运动学建模暂不需要）。
- **SLA**：服务等级（此处为送达时限基线）。
