# SwarmBalance v0.9：离线便携运行与端到端自检

v0.9 的目标不是改变论文/结项实验口径，而是提高**答辩机器、临时演示机器和开发机器上的启动成功率**。

正式实验仍推荐 README 中锁定的 Python 3.10 完整环境。便携模式只是在完整依赖临时不可用时，保证浏览器控制台、Greedy / GA / PSO 和主要交互功能还能从项目自带的本地 OSM 文件启动。

## 1. 两种启动模式

### 正式模式

```bash
python -m console.run
```

Windows 可以双击：

```text
start_console.bat
```

正式模式会严格检查：

- Python 3.10；
- OSMnx；
- OR-Tools；
- FastAPI / Uvicorn；
- 项目配置一致性。

该模式用于正式结项实验、论文结果复现和最终交付验收。

### 便携 Web 模式

```bash
python -m console.run --portable
```

Windows 可以双击：

```text
start_console_portable.bat
```

便携模式的行为：

- 若没有 `osmnx`，使用项目内置的 **OSM XML + pyproj 离线解析器**读取 `frontend/data/map/part_of_yangpu.osm`；
- 若没有 `pygame`，只关闭桌面 pygame 窗口，浏览器 2D / 3D 控制台继续可用；
- 若没有 `ortools`，Web 算法选择器会把 OR-Tools 标记为“不可用”，Greedy / GA / PSO 继续可用；
- 页面顶部会出现“离线便携”标记，避免把降级环境误认为正式实验环境。

> 便携地图解析器只解析本项目仿真所需的 `way[building]` 和主干 `way[highway]`。复杂 multipolygon relation 仍由 OSMnx 完整模式负责。因此便携模式适合演示与应急启动，不建议用来生成最终论文对比数据。

## 2. 一条命令做真实端到端自检

```bash
python -m console.selfcheck
```

它不是 mock 测试，而是实际走下面这条链路：

```text
本地 part_of_yangpu.osm
        ↓
真实 Environment
        ↓
10 架异构无人机 + 初始任务
        ↓
人工注入 P3 紧急任务
        ↓
真实 Greedy 单步调度
        ↓
事件日志
        ↓
运行态快照保存 / 恢复
        ↓
Web 静态地图几何导出
```

为了让启动检查在几秒内完成，自检确认真实初始任务已经生成之后，会把待调度池临时缩成一条自检任务。这个裁剪**只存在于 `console.selfcheck`**，不会影响任何正式仿真或实验。

## 3. 发布前统一检查

根目录新增：

```bash
python release_check.py
```

默认检查：

- Python 全项目编译；
- `console/` 单元测试；
- `ExperimentRunner` 单元测试；
- Web 内联 JavaScript 语法；
- `quick` / `conclusion` 两套实验计划 dry-run；
- 本地 OSM + Environment + 插单 + 快照的端到端自检。

正式结项机器最后再执行：

```bash
python release_check.py --strict
```

`--strict` 会额外要求 Python 3.10 + 完整依赖预检通过。

Windows 可直接双击：

```text
release_check.bat
```

## 4. v0.9 的真实验证记录

2026-09-11 的开发环境为 Python 3.13.5，未安装 OSMnx / pygame / OR-Tools。v0.9 在该环境下使用内置离线地图解析器完成了：

- 本地杨浦 OSM 文件解析；
- 108 个高层建筑约束对象加载；
- Web FastAPI 服务真实启动；
- `/api/meta` 与 `/api/snapshot` 实际请求；
- Greedy 真实 headless 仿真 300 步；
- GA 真实调度 1 步；
- PSO 真实调度 1 步；
- 人工紧急任务插入；
- 运行态快照保存与恢复；
- 33 项 console 测试 + 5 项 ExperimentRunner 测试通过。

这些结果只用于证明**系统主链路已经不再被 OSMnx / pygame 的 import 阶段硬阻断**，不作为论文中算法优越性的实验依据。

## 5. 答辩现场建议

正式答辩前优先准备 Python 3.10 完整环境，并运行：

```bash
python release_check.py --strict
```

同时保留 `start_console_portable.bat` 作为应急入口。若答辩机器临时出现 OSMnx / pygame / OR-Tools 安装问题，至少仍可以展示：

- 自由仿真；
- 运行时人工插单；
- GA / PSO / Greedy 调度；
- 无人机 / 机巢状态；
- 故障与机巢关闭；
- 运行态快照；
- 场景库；
- 2D / 3D 浏览器指挥台。

正式算法对比数据仍应使用完整环境和 `run_conclusion.py --preset conclusion` 产生。
