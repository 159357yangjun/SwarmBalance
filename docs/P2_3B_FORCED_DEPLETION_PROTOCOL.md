# P2.3b — 强制低电触发后的系统级配送代价实验

**目的**：P2.3 已完成的三档 30 seeds 从未触发欠电安全门。新实验需要一个真实激活门禁的**受控故障情景**，将“原场景未触发”与“低电故障实际造成的性能差异”分开。

## 不修改被测系统

- 原始代码：P2.1 `806d07653af52b83202ba232cb1f3e88dd9b7901`，修复代码：P2.2 `5bcc6cb9661dc250c11c578acbacc32c8b0d6f4f`。
- 两份代码通过 `git worktree add --detach` 严格检出，不在生产模型中引入实验开关，不更改 `Drone.update`、`Environment.step`、`consume_battery` 或 B 的默认 assigned 计费公式。
- 输入沿用 P1.2 已校准的三档外生冻结订单、10 种子、3600 秒、10 架机队与 OSM 地图。逐 seed 验证 config/tape 哈希与历史已归档输入一致。
- **实验性故障注入**：在每个回合首次遇到“正在执行订单、有待飞航点、不在换电中、距离所有已知换电站大于 100 米”的无人机时，在真正的 `Drone.update` 入口前把其电池人为置为 0 Wh，且仅注入一次。记录注入前电量、被移除能量、模拟时刻、无人机、任务、位置、航点与最近机巢距离。
- 两种代码分别从同一初始状态、同一任务流重放。它们的故障注入时间、对象、位置、目标航点与被移除的 Wh **必须完全一致**，否则硬失败；不人为对齐已经分叉的后续调度路线。

## 必须触发安全事件的双向门

- 旧执行器必须真实出现 `distance>0` 且 `last_energy_shortfall_wh>0` 的欠电运动；新执行器必须真实返回一次以上 `_flight_step_feasible=False`，且新执行器不得调用正距离、实际能量短缺的扣电移动。
- 先运行 1 seed × 2 个真实仿真回合的 **smoke gate**；仅成功后执行 3 档 × 10 seeds × 2 代码版本 = **60 回合、30 配对**。每对必须具备相同冻结订单哈希、配置哈希和故障注入快照，汇总缺任何 seed 即失败。
- 指标：完成数/完成率、未完成订单、仅已完成订单的平均延迟与超时率、真实飞行扣电、换电、总里程、最大队列、旧欠电飞行次数/短缺 Wh、新的拒绝尝试/被影响无人机及不同任务数。**拒绝次数计 drone-step，不能称之为受阻订单数；独立任务数另计。**
- 结果保存 JSON/CSV/Markdown、每个 seed 的原始配置/tape 与 Git SHA；Artifact 保留 30 天，出结果后需另行长期归档。

## 严格解释限制

1. 这是人为发生的**突然完全断电事件**，不是实测发生频率，也不是参数化电池自然衰减预测；被人为移除的电池电量不得当作飞行耗电。
2. 原始代码继续飞行可能增加“完成数”，但是非物理的欠电运动，不能把这种完成数当作正常配送能力。
3. 新执行器只执行“拒绝不可支付的下一航段”；**不**实现自动迫降、无电救援、可达换电站判定、订单重新分配。任务可能长期阻塞。
4. 本实验固定 assigned 模式，不验证 B/onboard 模式，不更改历史 E0/E1，不评估真实无人机安全性。
5. 旧 P2.2 全量 CI `#38031063942` 有与 G2 阈值灵敏度有关的 console 红灯，属于独立已知阻塞；本实验通过不代表该红灯已修。
