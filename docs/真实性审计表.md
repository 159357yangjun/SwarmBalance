# 真实性审计表（数字 → 原始来源 → 原文字段 → 测试条件 → 本地文件 → 派生算式 → 仿真参数）

> **本表的规则**：只登记我**本轮亲自打开原始页面/接口并逐字读到**的内容。
> 读不到的写"未取得"；不同官方页互相冲突的写"冲突未决"；算出来的标 derived 并给完整算式。
> **不采信任何转述（包括我自己上一轮的总结、以及外部 AI 给的结论）。**
> 取证时间：2026-10-03（本机 curl / WebFetch，HTTP 码与响应体大小一并记录）。

## 等级定义（三条轴，各自独立；2026-10-06 拆分）

旧体系把三件事塞进一个字母，于是出现过 `内容 A / 溯源 E` 和 `A(接口) + C(换算)` 这种一格两值的别扭写法
—— 那不是精炼，是分类维度不够用的症状。现在分三列：

**① evidence_grade —— 来源可信度（这个数字是谁给的）**

| 级 | 含义 |
|---|---|
| **A** | 厂商官方规格页/手册的直接值 |
| **B** | 原始公开实测数据（论文/数据集） |
| **C** | 由 A/B 可复算的派生值（附算式，**不得称"官方实测"**） |
| **D** | 假设值（无外部依据） |
| **E** | 未验证 / 存在冲突 |

**② traceability —— 溯源完整度（别人能不能独立回到那份原始件）**

| 档 | 含义 |
|---|---|
| **Complete** | 仓内留有原件或快照，且登记了 sha256 ⇒ 复核**不依赖任何别人的在线服务还活着** |
| **Partial** | 有明确出处且当前可重放，但核验依赖厂商页面**此刻的状态**（对方改版即失效） |
| **None** | 无外部依据，无从回溯 |

⚠ 判据里刻意做了两处收紧，并在此写明理由：
1. **厂商网页类来源最高只给 Partial。** 本轮实测它们确实可重放、且页面对哈希稳定
   （DJI 两次同为 `67de8b0eeb5f6f52`；ARK40 两次同为 `192489504d1d934e`，与登记值逐位吻合），
   表面上满足"API 可重放 ⇒ Complete"。但那是厂商随时可单方面改掉的外部状态，
   页面一改版 Complete 就悄悄失效而产物上看不出来。**Complete 的含义是"核验不依赖别人在线"，不是"此刻 curl 得通"。**
2. **traceability 评的是"这份东西能不能被取回"，不评"它是不是真品"。** 所以 OSM 底图的文件级是 Complete
   （原件+哈希在仓内、可离线复算普查），而"它是哪一次请求的产物"这件事仍属未证 —— 后者记在该条目的
   `provenance_gap` 字段里，**不靠把整条降级来掩盖**，也不靠升级来假装已证。

**③ transformation —— 处理过程（它被改过没有）**

| 档 | 含义 |
|---|---|
| **As-published** | 原文照抄，未经我方运算 |
| **Derived** | 经过计算 ⇒ **必须同时给出算式与复算命令**，否则本表拒绝生成 |
| **Local-extraction** | 从原始文件里提取/统计得出（如按 way 去重的元素普查） |
| **Assumption** | 无外部依据的设定 |

机器可读版：`data/provenance/truth.jsonl` 每条 parameter/source 都带这三个字段；
生成器 `docs/build_truth_dataset.py::_check_axes` 会拦住枚举越界、Derived 缺算式、
Assumption 却标 Complete/vendor_stated、以及 D 级与两轴不匹配这四类自相矛盾。

### 派生值（C 级，必须这样写）
| 派生量 | 完整算式 | 结果 | 项目现值 | 判定 |
|---|---|---|---|---|
| 空载单位距离能耗 | 3968.8 Wh ÷ 28 km | **141.743 Wh/km = 0.141743 Wh/m** | heavy `consumption_base` = **0.142 Wh/m** | ✅ 差 0.18% ⇒ **这就是 142 的标定依据** |

| 满载单位距离能耗 | 3968.8 ÷ 16 | 248.05 Wh/km | 0.142×1.75=0.2485 Wh/m | ✅ 自洽 |

## 10. 假设参数的敏感性定级（S1 / S2 实测）

> 规则：不声称"180 秒合理"或"SLA 符合行业"。只回答**它们在合理区间内变化时结论会不会动**。
> 两轮都是 greedy + C-1/C-2 + paired seeds 40901–40905（n=5/格），默认配置未被修改。
> n=5 双侧符号检验最小可达 p=0.0625 > 0.05 ⇒ 全文只报"方向一致/幅度大小"，不称显著。

### 10.1 S1 换电时间 `swap_time_seconds ∈ {60, 180, 300}` —— **高度敏感**

前置门 `console/test_swap_time_gate.py`：该值在配置里有 **7 处**（5 station + nest + drone），
运行时只有 station 值生效（`environment.py:816` → `drone.py:206-208`），而 runner 的
`_deep_merge` 对 list 是整体替换 ⇒ 只写一个 station 会静默丢掉其余 4 站。变异面"只改 station"实测转红。
`frontend/drone.py:25` 的模块级冻结被钉成会红的断言（须跑子进程），故每格独立进程。

| 指标 | swap60 | swap180 | swap300 | 配对方向(60→300) |
|---|---|---|---|---|
| C-1 完成率 | 0.8149 | 0.7297 | 0.6473 | 5/5 同号 ↓ |
| C-1 超时率 | 0.1943 | 0.2328 | 0.2580 | 5/5 同号 ↑ |
| C-2 完成率 | 0.5056 | 0.4337 | 0.3730 | 5/5 同号 ↓ |
| C-2 超时率 | 0.3497 | 0.4956 | 0.5790 | 5/5 同号 ↑ |
| C-1 平均时延 | 95.05 | 98.12 | 113.34 | **4/5**，1 例反向 ⇒ 撤回单调断言 |
| C-2 平均时延 | 238.57 | 377.26 | 404.98 | 5/5 同号 ↑ |

⚠️ **我预先写下的预期被实测驳回**：原以为换电不吃能量 ⇒ `total_energy` 不敏感。
实测它随换电变慢**下降 21%**（C-1 26356→20724）。机制是间接路径：
换电慢 → 机巢占用久 → 可用运力降 → **完成任务更少** → 飞行距离更短 → 能量更低。
同向证据：总飞行距离同步降 23%。⇒ `total_energy` 是服务量的下游指标，
**单独读它会得出"换电慢反而节能"的错误结论**。

对外表述改为：情景参数，且系统对其取值敏感 ⇒ 报告须给区间不给单点。
原始读数 `docs/取证输出/s1_swap_sensitivity.txt`。

### 10.2 S2 SLA `{Loose 540+30kg, Current 420+24kg, Strict 300+18kg}` —— **评价敏感**

判别问题不是"超时率会不会变"（定义使然，必然变），而是**它改的是评价口径还是调度行为**。

消费链（`console/test_sla_consumption_gate.py` 逐条钉住，摘掉 urgency 的变异面实测转红）：
生成 `task.py:369-370,520-527` → 写入 `environment.py:1297`/`task.py:549` →
统计 `environment.py:391-393` → **决策** `environment.py:1503-1512`(ttlj 进观察空间)
→ `greedy/scheduler.py:174,180-186` → `matching.py:34-46`（urgency = 1 − remaining_time/300）。
不进决策：`run_ga/run_pso/run_ortools/scheduling_interface` 的 deadline 引用数 **0**；
`overdue_penalty` 只在 `_reward()` 内；贪心的 `-inf` 拒因只有容量（**不存在按时限拒单**）。

| 类别 | 指标 | 结果 |
|---|---|---|
| 评价类 | 超时率 | C-1/C-2 × Strict/Loose 四个对比全部 **5/5 同号**，幅度 +0.06~+0.15 |
| 评价类 | 平均时延 | 四个对比全部 **5/5 同号**（Strict 升、Loose 降） |
| 行为类 | 生成任务数 | 三档 **Δ=0** ⇒ 分母未动，可比性成立 |
| 行为类 | 完成率 / 完成任务数 | C-1 升3/降2【混杂】；幅度 ≤0.028 |
| 行为类 | 总飞行距离 | C-1【混杂】、C-2【多数同向】但仅 ±0.5% |
| 行为类 | 无人机利用率 | 变化量级 1e-4 ⇒ 实质不动 |

挂账异常（不当证据）：C-2 `总能量消耗` Strict vs Current **5/5 同号**(+1.8%)，
但同格里程只"多数同向"、完成任务数"方向混杂" ⇒ 里程与能量不自洽，
候选解释是换电时机改变（换电次数 Δ=[-1,-1,0,-1,-1]）而非飞行量改变。**机制未定**，
需专门记录每次换电时刻与起飞电量才能判。

定级：**评价敏感（主）+ 行为影响可测但弱**。SLA 经 urgency 确实接进了贪心打分，
但在本区间内没有观察到足以改变系统表现的决策效应。
⇒ **超时率必须与 SLA 档位绑定报告；单独给"超时率 X%"无意义。**
