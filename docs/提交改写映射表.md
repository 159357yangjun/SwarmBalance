## 口径（每个数怎么来的）

| 量 | 值 | 怎么算 |
|---|---|---|
| 不可达（旧指针 + 无关悬空对象） | 29 | 全量 commit 减去 `rev-list HEAD` 可达集 |
| ├ 改写配对出来的旧指针 | 18 | 有同 subject+tree+author 的活对端 |
| │  ├ 曾当过 `main` 的头 | 13 | sha 出现在 `git reflog refs/heads/main` |
| │  ├ 从未当过头（dry-run 或被替换的中间父） | 4 | 不在 reflog —— 可复验 |
| │  └ 标题/作者同而 tree 不同（改写动了内容） | 0 | 放宽 tree 再配一次才叫得出名字 |
| └ 与改写无关的悬空对象 | 12 | `classify_dangling()` 按 stash / 孤儿根归类 |
| 恒等式（配对 + 悬空 = 不可达） | 成立 | 不成立就退出码 1 |
| 活分支上 message 仍含 `^MSG;` 的条数（欠账） | 0 | 一条 `git log --format=%B` 扫全部；欠账只进这一行，不进退出码 |
| 需要修的问题数 | 0 | 非 0 时 `--verify` 退出码 1 |

## 为什么引用要靠标题而不是 sha

- 改写只动 message 尾部一行，**标题不变**，所以标题是稳定的主键：
  `git log --format="%h %s" | grep -F '<标题片段>'`
- 旧对象只靠 reflog 活着。`git gc` 按 `gc.reflogExpire`（默认约 90 天）回收后，
  这些对象从对象库里消失，`git cat-file -t <旧sha>` 直接失败 —— 届时表里对应的
  **那一整行会不见**（不是变成另一类）。所以这张表不能当永久台账：要长期引用，
  记标题与上面那条 `git log --grep` 复算式。表缩短这件事 `--verify` 兜不住
  （它只核「盘上这份与现在算出来的一致」），兜得住的是恒等式：每次生成时
  「配对 + 悬空 = 不可达」必须成立，不成立直接退出码 1。
- 只能问"同一位置的新旧两端"：`git diff --quiet <旧> <活>` 必须 rc=0。
  `git diff <旧> HEAD` 非空**不是缺陷**（那之后还有新工作），别拿它当判据。
