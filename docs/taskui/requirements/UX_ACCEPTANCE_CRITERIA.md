## 1. 基础验收制度

- 每项需求必须关联任务 ID（[TASK_INVENTORY](TASK_INVENTORY.md)）、现有入口和 API、业务风险、验收观测。
- 以当前 master 同一运行环境、数据源、Seed、视口和任务初始条件建立基线 A，G1 原型/未来实现为 B。
- 对 A、B 采用相同任务脚本并记录：完成/失败、错误动作、返回次数、有效执行路径、时长（从出示目标到对应状态可证实）、反馈是否被使用者察觉、运行状态是否误判。不得凭源码推导统计数字。
- 无法运行、缺可用依赖、缺设计原型、版本不一致时写 **BLOCKED / NOT MEASURED**；不可写 PASS。
- 涉及科研口径的可比性、配置错误写入和数据误归因是**硬性阻断项**，不能由“操作更少/页面更美观”抵消。

## 4. G1 信息架构输入包与审查门

**已确认信息**：界面导航以工程分层命名且互斥切换；主要控制集中在顶栏；地图检查器为覆盖层；调度列表和实时事件在控制层；态势/快照/演示放在数据层；实验编排和对比放在算法层。代码证据：`console/static/index.html:601-655,675-783,811-1078,1089-1152,2663-2687`。

**G1 候选结构（仅需求级，不是最终路由）**：

- 仿真运行：T01/T02/T03/T04/T05/T08/T10，地图主区 + 运行控制。
- 诊断监控：T04/T06/T07/T09/T11/T17，地图与事件/任务链连续关联。
- 实验分析：T17/T18/T19/T20，数据来源、口径与结果优先。

## 5. 当前未验证与假设登记

H01（跨视图断点）：`showMap=false` 导致地图→调度→地图产生额外认知/导航负担；**静态切换属实，负担待测**。  
H02（顶栏拥挤）：低频配置与高频控制混排降低发现速度；**混排属实，效率待测**。  
H03（检查器遮挡）：地图 inspector 覆盖可能遮挡关键轨迹；**覆盖属实，实际影响待测**。  
H04（保存语义）：用户可能将场景、快照、预设混淆；**数据生命周期不同属实，误判率待测**。  
H05（分步保存）：第二次配置写入或重建失败时可能产生部分提交；**分段请求属实，具体失败结果待故障注入**。  
H06（科研混淆）：实时统计和 `/api/compare` 来源不同，用户可能错误混用；**来源不同属实，误判率待测**。
