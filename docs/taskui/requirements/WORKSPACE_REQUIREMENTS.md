# WORKSPACE_REQUIREMENTS｜仿真工作区空间与交互需求

> TASKUI-SB-UI-02 · G1 输入草案，不是设计稿。证据限定于 `master@2ab60c69a806a22d7ba20353dee0571752a0e8e5` 的源码和仓库文档。下述“应”均为建议，实施须经过 G1/G0 设计审查。

## 1. 当前空间组织（已由静态代码确认）

- 单个 `console/static/index.html` 同时承载 Vue 组件模板、Canvas 2D、Three.js 3D、ECharts 图表、状态/请求方法；它不是已组件化路由系统。
- 左导航对应“实现层”（地图）、“控制层”（调度）、“算法层”（对比/实验）、“数据处理展示层”（态势/快照/演示）、“规范”（内嵌规范）。`goPage` 实现互斥的 `showMap` 和 `tab`。
- 地图 `canvas-wrap` 作为 main 主体，但选中实体的 inspector 绝对定位覆盖在地图右上方，宽度 `min(370px,46%)`；控制与算法区的右侧 `dock` 提供相似的实时信息。
- “配置”“场景编辑”“场景库”“新任务”用模态弹窗；取点时临时关闭弹窗，再在 2D 地图点选，完成后回弹窗。
- 窄屏时 `dock` 可被隐藏；本轮未做真实响应式布局可用性测试。

## 3. 空间优先级而非硬编码尺寸

**地图主工作区**：运行/追踪任务期间保持最大可读区域；对象检查器不能无提示遮住目标飞机、任务线或禁飞区。由于未实测分辨率和遮挡比例，**不指定像素宽度或百分比数值**，由 G1 通过 1366×768、1920×1080 等测试视口评估（这些仅是计划测试环境，不是现有实测）。

**配置区**：仅在准备场景/具体编辑目标时展开；表单字段分组为任务生成、机队、机巢、算法超参和布局。需要展示数据源 random 与 CSV/GeoJSON 可编辑边界。

**实时监控区**：任务池、任务链、机巢队列、事件与汇总 KPI 根据诊断意图渐进披露；不要为每项数据永久占据地图主区。跨区对象 ID、运行时刻、状态必须一致；若为纯静态历史事件，不能误用当前状态解释历史。

**结果分析区**：批次状态、来源、口径、单位、指标、证据包优先；实时图表与不同实验结果要明确分域。尚不存在任意历史批次选择接口，不能先画成已经能切换历史 run 的设计。

## 4. 危险操作反馈契约（只定义界面需求）

1. **重置/配置/场景库应用/演示预设/快照恢复**：操作前能辨识即将丢失或替换的“当前运行态”；操作中显示进行中，成功后回显真实算法/Seed/step，失败保留真实错误信息。
2. **结构性编辑**：必须提示会重建，且不支持非 random 数据源保存；快照跨环境代不兼容应可识别，不能把其“存在”表示为“可恢复”。
3. **任务更新/故障/关闭/补能**：指出对象 ID 和变更后资源状态；“暂停自动订单流”不得表达为暂停无人机运动。
4. **实验**：是否正在运行、批次输出位置、结果是否可比、可否下载正式证据包应分开陈述。
5. 上述反馈要求**不允许把 UI 文案当作服务端事务保证**；`saveConfig()` 的分段 API 调用属于需核对的部分提交风险。

## 5. 给 G1 的不可变约束与待决问题

不可变：不增加未经确认的业务流程；不重构内核；已有任务/对象/实验语义不变；科研 compare gate 不退化；保持 2D 地图取点工作流和便携模式能力。

待决（必须通过用户走查）：地图与调度是持续双列还是可切换抽屉；监控坞的常驻最小集；高频动作按使用情境排序；诊断任务要不要保留更多事件（这会涉及新 API/产品需求，当前不能作为必做项）；场景库与快照如何命名最不易混淆。
