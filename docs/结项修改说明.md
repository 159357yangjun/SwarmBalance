# SwarmBalance 结项对齐修改说明

本轮修改以《群智优衡——异构无人机集群三维协同调度仿真平台》大创申请书为验收边界，优先补齐“异构能力匹配 + 任务链局部搜索 + 机巢动态调度”的主线，不删除现有 PSO / MARL / Web 控制台等扩展能力。

## 本轮已完成

1. **GA 正式接入异构能力—需求匹配**
   - 新增 `backend_si/matching.py`，统一载重、速度/时效、续航/距离三维匹配度。
   - `chain_codec._DroneState.try_append()` 在硬约束可行的前提下，把匹配度作为软奖励加入增量代价。
   - 配置项：`chain.w_match`。

2. **补齐申请书要求的“任务分配后局部搜索”**
   - 贪婪分割形成初始任务链后执行 best-improvement 局部搜索。
   - 邻域包含：链内 swap、链内 2-opt 式片段反转、跨链 relocate + 任意插入位置。
   - 所有候选解都重新执行载重、电量安全余量、时间窗约束校验，不接受不可行改动。
   - 配置项：`chain.local_search`、`chain.local_search_passes`。

3. **修正文档口径**
   - MARL 实际算法改为 IQL / VDN / QMIX，不再写成 PPO。
   - 明确当前已存在 FastAPI + Vue3 + Three.js Web 控制台，不再写“项目无 Web 后端”。
   - GA 固定为申请书主线：排列编码 + 贪婪分割 + 能力匹配 + 局部搜索；Greedy / OR-Tools 为申请书基线，PSO / MARL 为扩展对比。

## 结项答辩建议口径

> 本项目面向城市应急与低空物流场景，针对机巢分布、无人机异构能力、任务多样性与公共资源有限四重约束，构建异构无人机协同调度仿真平台。核心算法以 GA 排列编码为基础，经约束感知的贪婪分割生成任务链，再通过能力匹配和局部搜索优化任务分配与执行时序；机巢侧采用动态优先级机制处理起降/充电资源冲突。系统以 Greedy 与 OR-Tools 为基线，并扩展 PSO / MARL 对比。

## 下一轮建议

优先补“结项实验一键运行”：固定同一批随机种子，自动完成算法对比、任务密度敏感性、异构机型配比敏感性、机巢泊位数敏感性，并输出 CSV 与论文/答辩可直接使用的图表。
## 本轮新增：一键实验编排器

在不改变“自由仿真调度平台”定位的前提下，新增独立的实验自动化入口：

- `run_conclusion.py`：根目录一步执行命令；
- `run_conclusion.bat`：Windows 一键入口；
- `experiments/runner.py`：统一实验编排、汇总、出图；
- `experiments/worker.py`：每个 episode 在独立子进程运行，避免模块级配置串值；
- `experiments/presets/quick.yaml`：快速自检；
- `experiments/presets/conclusion.yaml`：标准结项实验；
- `experiments/presets/paper.yaml`：高重复次数论文实验；
- Web 控制台新增“实验”页签，与命令行共用同一 Runner。

实验默认自动完成：算法横向对比、任务总量敏感性、机巢泊位数敏感性、异构机队配比敏感性；同时输出原始 CSV、汇总 CSV、图表和 `summary.md`。

**关键安全设计：** `config/config_loder.py` 支持 `SWARM_BALANCE_SIM_CONFIG`，实验子进程读取隔离配置副本，不会为了批量扫描反复覆盖用户的 `config/simulation.json`。因此平时仍可在 Web 控制台自由调参、播放、暂停、单步；需要结项证据时再进入“一键实验”。

本环境已完成编译、预设计划和配置隔离单元测试；由于当前执行环境缺少 `osmnx`，无法完成真实 OSM episode。项目自身 `requirements.txt` 已固定 `osmnx` 等依赖，按 README 的 Python 3.10 环境安装后即可实际运行。



## 本轮新增：交互式自由仿真调度

为避免项目退化成“纯算法对比系统”，Web 控制台继续向真正的仿真调度平台推进：

- 支持播放、暂停、单步与 1x / 2x / 5x / 10x 仿真；
- 支持在运行过程中人工插入任务，不重置环境、不修改主配置；
- 提供“紧急医疗 / 重货配送 / 普通订单”快速预设；
- 任务起终点既可随机生成，也可在 2D 地图点击选点；
- “调度”页实时展示无人机任务链、载重、电量、剩余航线；
- 展示机巢泊位占用、等待队列、等待时间与动态优先级得分；
- 记录任务到达、分配、链式插入、完成、泊位等待/获准、换电完成等事件。

这使申请书中的“滚动时域调度、新任务插入与局部重规划”不再只是后台算法描述，而能够在答辩现场直接演示。批量实验仍保留为独立“实验”页，用于提供论文/结项的可复现实验证据。

## 本轮新增：可点击调度指挥台（v0.4）

在 v0.3 的自由仿真基础上，进一步把“看动画”升级为“看决策”：

- 2D / 3D 地图上的无人机、任务和机巢均可直接点击；
- 无人机详情显示异构机型、速度、电量、载重、剩余航线和当前任务链；
- 机巢详情显示有限泊位占用、动态优先级排队和换电时长；
- 任务详情覆盖 pending / assigned / in_progress / completed 全生命周期；
- 对待调度任务增加“候选无人机解释”视图，展示能力匹配分、ETA、估算距离以及载重不足、电量不足、预计超时等原因；
- 调度事件日志携带任务/无人机/机巢实体引用，可点击回看对应对象。

这里特别区分“解释层”和“算法层”：候选无人机排名只是为了让答辩现场能理解为什么某类机型更适合某类任务，最终分配仍由当前选择的 Greedy / GA / PSO / OR-Tools 调度器真实输出，避免为了展示而另造一套决策逻辑。


## v0.5 运行时资源状态变化

在不改变申请书核心主线的前提下，交互式仿真新增运行时场景事件：无人机故障停飞/恢复、机巢临时关闭/重开。故障机会退出当前可用机队，其未完成任务回收到待调度池；机巢关闭后停止接收新的补能请求，等待或前往该站的无人机改道至其它开放机巢。事件不会重置当前仿真，用于直观展示滚动时域调度与局部重规划能力。

该功能属于系统演示层的增强，不改变 GA + 能力匹配 + 任务链局部搜索 + 机巢动态优先级的结项算法主线。


## v0.6 场景编辑与运行控制

在已有“自由仿真 + 动态插单 + 事故注入”的基础上，进一步补齐系统作为**可操作仿真平台**的场景设计和运营控制能力：

- Web 顶部新增“场景编辑”，可在当前地图上增删/移动机巢、修改泊位数，新增/移动/删除圆形禁飞区；
- 场景保存执行边界、机巢 ID、禁飞区冲突和建筑物内部校验；重建失败自动回滚配置，避免损坏可运行场景；
- “调度”页可暂停/恢复自动订单生成，以便答辩现场冻结新增订单、专注观察当前任务池；
- 待调度任务可在运行中修改优先级、剩余 SLA、重量与任务类别，并提供“一键升为紧急任务”；
- 可人工将无人机调往最近开放机巢补能，正在执行任务的无人机挂起剩余航线，经过机巢真实有限泊位仲裁后换电并恢复任务。

这里保持两个层次：**运行时控制**不重置环境，用于展示滚动重调度；**场景结构编辑**会写回 `simulation.json` 并明确重建环境，用于实验/演示前设计机巢网络和禁飞区。这样既保留自由操作感，也避免对结构性变化做不真实的“无缝热切换”。


## v0.7 可复现演示与运行态快照

在 v0.6 的自由场景编辑基础上，本轮重点提高**结项答辩的可复现性与现场稳定性**：

- 内置“应急医疗高峰 / 机巢拥堵 / 故障韧性 / 标准综合”四套演示场景，自动应用场景参数、推荐算法和固定 Seed；
- 演示场景采用“下一幕”剧本自动编排人工操作，但每一步仍调用真实调度与仿真接口，不引入演示专用决策逻辑；
- 首次进入演示模式会保存进入前的 `simulation.json` 与算法/Seed，可一键恢复，避免答辩预设污染平时自由仿真配置；
- 新增当前服务内的运行态快照，可把故障/插单/拥堵前后的完整动态节点保存并恢复，并恢复 Python/NumPy 随机数状态，便于从同一节点重复同一答辩场景；
- 趋势指标改由后端持续采样，浏览器刷新后仍可查看此前运行趋势；新增运行态势摘要用于快速识别紧急积压、低电、停飞与机巢排队。

该增强属于**仿真系统交互与复现层**，不改变结项算法主线：GA 排列编码 + 贪婪分割 + 能力匹配 + 局部搜索，机巢侧继续采用有限泊位与动态优先级仲裁。


## v0.8 产品化收口

- 顶部新增“场景库”，将可复现**初始配置**持久化为 JSON；运行态快照继续只负责当前服务内的动态节点恢复。
- 态势页增加资源摘要与动态操作建议，首次进入提供使用引导。
- 启动入口增加 Python/依赖/配置预检，Web 配置保存与场景导入共用一致性校验。
- 修复 Web 热重建后回合步数上限未刷新问题。
- 当前 Web 状态刷新机制为 REST 轮询/批量步进；结项材料不要写成已实现 WebSocket/SSE 推送。

完整审计见 [`产品化收口与结项口径审计.md`](产品化收口与结项口径审计.md)。


## v0.9 离线便携、端到端自检与发布检查

- 地图加载改为“OSMnx 完整模式优先 + 本地 OSM XML 轻量回退”，答辩机缺少 OSMnx 时浏览器控制台仍可使用项目自带地图离线启动；
- pygame 桌面 Viewer 延迟导入，Web/headless 仿真不再被桌面依赖阻断；
- Web 根据运行时能力自动禁用不可用的 OR-Tools，并显示“离线便携”状态，避免环境降级被误认为正式实验；
- 新增 `console.selfcheck` 与 `release_check.py`，正式提交前可一条命令完成真实主链路和轻量测试检查；
- 已在当前缺少 OSMnx / pygame / OR-Tools 的开发环境实际跑通本地地图、Web 服务、Greedy / GA / PSO headless 调度。该结果属于稳定性验证，不替代 Python 3.10 正式结项实验。
