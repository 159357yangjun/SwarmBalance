## 6. C2/C3 门禁缺口分析：这一条能不能用一条不依赖现场违规样本的门守住？

按我自己的纪律先排除三条走不通的路：**无可读取状态则写不出不会永绿的门**；**期望值 0 的夹具给不了牙**；**加 unknown 三态若无覆盖率上限就是逃生口**。

**结论：一半守得住、一半守不住，必须分开登记。**

### 6-A 守得住的那半：前提条件本身有可读状态 ⇒ 能写非常驻红的门
"可达"的前提是**存在一个 `is_free=True` 且该机仍挂 assignment 的时刻**。这个前提有两种可读取状态：
1. **源码层（静态）**：`is_free = True` 的赋值点是有限集合（本轮枚举＝drone.py:88/:281/:342、environment.py:545 共 4 处）。可建一条**结构性门**：断言"is_free=True 的赋值点白名单 == {这 4 处}"，新增第 5 处即红。
   - 为什么它不会永绿：它的期望值是**白名单相等**而非"抓到违规"，所以现场没有违规样本时它照样能红（多一个赋值点就红）。这正是我需要的性质。
   - 牙从哪来：变异面＝临时插一行 `d.is_free = True` 到别处，门必须红（两面夹具）。
   - 残余弱点：白名单要随合法重构更新，属于"人工约定 + 门兜住遗忘"，不是纯自动。
2. **运行时层（动态）**：本轮那个 `free_with_assignment` 计数器其实**可以常驻**——把它做成门，判据写成**不变量**（每步末恒为 0）而非阈值。
   - ⚠ 但按纪律这条**单独看是给不了牙的**：期望值为 0 的不变量在现场无违规时永远绿，无法自证它会拦。所以它必须配一个**注入面**（构造一个 is_free∧assignment 并存的状态，门必须红）才算有牙；而"能否构造出来"本身就依赖 §6-A-1 那个静态白名单先成立。
   - ⇒ 判定：**动态不变量只能当第二证人，不能当主门**。

### 6-B 守不住的那半：语义归属没有可读取状态
C3 的"is_free 是否只承载 Q2 这一个语义"是**关于意图的命题**，代码里没有对应可读状态——新代码完全可以读 `drone.is_free` 却拿它回答 Q3（服务已终结吗），语法合法、静态扫不出歧义。
- 我能做的最接近的东西是 C4 那种**文本扫描门**（禁 `current_load` 与裸零比较），但对 is_free 不存在等价的"错误写法签名"：`if drone.is_free:` 在两种语义下长得一模一样。
- ⇒ **明写：这一条守不住。** 只能靠 (1) 文档约定（docs/C3_state_field_audit.md §1.2 的语义标注表）、(2) code review 时人工核对新增消费者在问哪个问题、(3) 若未来真要机器守，得先把语义拆成两个字段（即 C3 判"不需要拆"的那件事反过来做）——那时才有可读取状态可钉。
