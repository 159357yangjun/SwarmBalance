# Phase 1B-2 A 方案结果 —— 约束式罚分把超时率降下来了（含一处我判断错的方向）

日期 2026-10-05。对象：`score += W · min(0, slack_full / 300)`，其中
`slack_full = remaining_time − ETA(取货) − distance(取货→送货)/speed`。
产物：`docs/取证输出/phase1b2_constraint_paired_experiment.txt`（72 cells）。

## 1. 先记我的方向判断错了

我在设计文档 §4 写的是"罚分只在注定赶不上时起作用，不会去奖励半程从容的单 ⇒ 预期改善"，
但同时又把 **A 标成"改动最小、语义正确"的推荐项**、并预测"w=0.4 一档就够"。
实测：**w=0.4 已经显著有效，w=1.2 更好**——我把权重档位猜小了，而且低估了它的量级。

更具体地说，我当时没预料到 `min(0, slack/300)` 的**实际触发率**：
step=0 快照上 48/48 候选零贡献（G13e 实测），我据此一度怀疑"这分量整局都不起作用"。
真实数字是——

| w | 打分事件 | **被罚** | 最小贡献 |
|---|---|---|---|
| 0.0 | 1604 | 0 (0.00%) | — |
| 0.4 | 1618 | **1148 (70.95%)** | −4.4339 |
| 1.2 | 1609 | 1112 (69.11%) | −14.0468 |

⇒ **初始帧零触发 ≠ 整局零触发**。派单发生在机队忙碌之后，那时真余量普遍为负。
教训与上一轮同源：**快照不能替代 episode**（我已经为同一个错误撤过一次追溯链，这次是第二次撞同一块石头，只是方向相反——上次是把"有作用"外推过头，这次是把"无作用"外推过头）。

## 2. 主结果：超时率（greedy 面，E=euclid / P=planned）

| fixture·seed | w=0.0 | w=0.4 | w=1.2 |
|---|---|---|---|
| C1 40901 | 0.2736 / 0.2667 | 0.1667 / 0.1667 | **0.1019 / 0.1019** |
| C1 40902 | 0.1963 / 0.1802 | 0.1553 / 0.0971 | **0.1515 / 0.0481** |
| C1 40903 | 0.2613 / 0.3130 | 0.1485 / 0.1485 | 0.1682 / 0.1682 |
| C2 40901 | 0.5270 / 0.4533 | 0.3750 / 0.4110 | 0.3026 / 0.3472 |
| C2 40902 | 0.4667 / 0.5065 | 0.4000 / 0.4000 | 0.3913 / 0.3913 |
| C2 40903 | 0.5205 / 0.5000 | 0.3867 / 0.3867 | 0.4179 / 0.4179 |

**6/6 个 seed×fixture 全部下降**，无一例外。C1 40901 从 0.274 → 0.102（迟到单 29 → 11）。

平均时延同向且幅度更大：C1 40901 121.2 s → 22.5 s；C2 40901 403.0 s → 94.7 s。

代价在吞吐上（这是必须如实报的部分）：

| fixture·seed | 完成任务数 w=0.0 → 0.4 → 1.2 |
|---|---|
| C1 40901 | 106 → 102 → 108 |
| C1 40902 | 107 → 103 → 99 |
| C1 40903 | 111 → 101 → 107 |
| C2 40901 | 74 → 72 → 76 |
| C2 40902 | 75 → 70 → 69 |
| C2 40903 | 73 → 75 → 67 |

⇒ w=0.4 档普遍少完成 4~10 单；w=1.2 在 C1 40901/C2 40901 反而回升，**符号不一致**。
即：**这不是免费午餐，是"少接赶不上的单"换"履约率"**。而总飞行距离基本不动（±1%）⇒
省下来的不是里程，是接单量。

⚠ n=3 且两面混着看，**不做显著性宣称**；能宣称的是"6/6 同号"这一形状。

## 3. 判别式与对照面

- **GA 面 72 格中所有 KPI 逐位不变**（脚本核对：非零 Δ 格子数 = 0，三档权重都一样）
  ⇒ 罚分没有渗进后端，阴性对照继续成立；也再次证明 `eta_calls=0` 那一行的结论没被本轮破坏。
- **W=0 与既有基线逐位等价**（G11，96 条候选腿 × 两面，不一致 = 0）⇒ 默认权重 0.0 仍然守住"本次实现不改生产行为"。
- **单侧性由 G13e 直接锁**：81 条候选里最大贡献 ≤ 1e-12（不允许任何正贡献），
  且"slack<0 却没被罚"的数量必须为 0。这条正是 1B-2 否掉奖励式的全部意义。
- **provider 维度在本轮几乎消失**：w≥0.4 时 E/P 两面多数格子逐位相同（如 C1 40901 w=1.2 全是 0.1019/108）。
  机制解释：罚分项一旦主导排序，绕障距离带来的那点分数差就被压掉了——
  也就是说 **ETA 与距离两个口径不是叠加关系，而是 ETA 会淹没距离效应**。
  这条对 1B-3 有影响：届时不能再假设"三层各自独立可测"。

V6 这一条要如实记成**我的门的失效**：G13e 只在 step=0 快照取样，而那里自然零触发 ⇒
两面都是 0、差异看不见。我上一段刚写下"step=0 零触发不代表整局零触发"，
紧接着就用一个只在 step=0 取样的门去锁语义 —— 同一个外推错误的第二次犯法，方向相反。
修法不是放宽判据，而是换成【构造夹具】：近单(取货100m+送货20m)与远单(取货100m+送货1000m)
同 remaining_time=30 s，只有送货腿不同 ⇒ 任何漏算送货腿的实现都会让两者 slack 相等。
⇒ 门数 11 → 12（套件现算 34 文件 / 282 用例）。

## 5. 建议（不自行决定）

数据支持的不是"选哪个权重"，而是**这个分量应该以什么身份存在**：
- 若目标是**答辩/论文里的算法有效性**：w=1.2 的"超时率 6/6 下降 + 时延数量级改善"是能讲的，
  但必须同时报吞吐下降，否则就是挑好看的半边。
- 若目标是**产品默认配置**：建议 **w=0.0 保持不动**（现状即如此），把它作为"可开启的履约保护"，
  而不是替换现有贪心基线——因为 S2 那轮已证 SLA 本身是无来源情景参数，
  用一个无来源阈值去驱动默认调度行为，等于把一个假设升级成生产逻辑。

要我做的话，顺序是：补 V5/V6 变异 → 加一组 n=8 的同号性检验（现在 n=3 不足以报"稳定"）
→ 再决定是否给 config 开一个显式开关。
