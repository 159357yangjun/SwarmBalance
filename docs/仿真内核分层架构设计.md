# 仿真内核分层架构设计（重做版）

> 依据：用户提供《仿真软件开发核心问题》框架（状态优先 / 渲染只是输出）+ 对现有代码的核查。
> 配套文档：`世界逻辑规格书.md`（世界规则事实源）、`架构与界面改造方案.md`（UI/展示层改造）。
> 本文件解决"仿真内核怎么分层、怎么与渲染解耦、怎么保证确定性与可测"。

---

## 0. 先给结论

用户那份框架的本质——**状态优先，渲染只是输出**——现有项目**大方向已经吻合**，而且是"碰巧做对"多于"设计保证"：

- ✅ 服务端无头跑 `Environment(visualize=False)`（`console/sim_session.py:113/582`），渲染库（pygame/three）**只在桌面端 `run_visual.py` 按需 import**，Web 路径零耦合。
- ✅ `SimSession.snapshot()` 把整世界状态（map/drones/nests/tasks/stats/history）序列化；`_history` 双端队列（maxlen=360）已做**状态回放**。
- ✅ 交互是"客户端发命令→服务端改状态→下一快照反映"（`server.py` REST），不是改像素。
- ✅ 已用随机种子（`set_seed` / `reproducibility.json`）。

**但框架要求的"设计保证"还差六处**，下面逐条给出现状评分与目标设计。

---

## 1. 八条原则 · 现状评分

| # | 框架原则 | 现状 | 评分 | 缺口 |
|---|---|---|---|---|
| 1.1 | 碰撞检测/响应（CCD、冲量而非 setPosition） | 无刚体碰撞；楼宇/禁飞**在规划期**绕开（`plan_route_around_buildings`/`no_fly.path_blocked`） | ⚠️ | 飞行中无 drone-drone / drone-建筑碰撞；属"运动学仿真"取舍，但未文档化 |
| 1.2 | **固定时间步长、与渲染解耦** | Web 是**客户端拉一步算一步**（`/api/step(count)`），无服务端固定时钟 | ❌ | 仿真推进速率随客户端请求节奏变化，未结构性保证"物理与帧率解耦" |
| 1.3 | 数值稳定性（阻尼/误差校正/质量悬殊） | 直线运动 + 线性能耗，无积分爆炸风险；但**飞行中无越界/NaN 防护**（`environment.py` 仅在建任务时查边界 1179-1183） | ⚠️ | 缺位置 clamp / NaN 守卫 / 卡死检测 |
| 2.1 | 每个物体独立状态存储 | 实体是对象（Drone/Task/Nest）✅ | ✅ | 但缺统一 `WorldState`，实体散在 `Environment` 各 list |
| 2.2 | **可见性是渲染属性≠存在属性，不删实体** | 渲染端（three.js）按快照建/删对象，无显式"visible 渲染标记"契约 | ⚠️ | 未文档化"遮挡≠销毁"不变量 |
| 3 | **渲染层不反向影响状态** | 已做到（命令式交互）✅ | ✅ | 需写成硬契约，防止 future 回归 |
| 4 | 确定性（同种子同结果、单线程、快照可复现） | 有种子；单线程 ✅ | ✅ | 缺**快照往返确定性测试**（save→load→step 须与连续 run 一致）；随机源是否全集中未审计 |
| 5 | 分层：Core / SceneManager / Render / UI | 有 Core（`Environment`）+ Render（two impl）+ UI（server） | ⚠️ | `Environment` 是 **91KB 上帝类**，把物理步进+需求生成+机巢仲裁+指标+奖励+（条件）查看器混在一起；无独立 SceneManager |
| 6 | 物理引擎选型 | 未用（正确） | ✅ | 需**显式决策并记录**：运动学调度仿真不引入 PyBullet（理由见 §4） |
| 7 | 自动化测试读核心状态，不靠肉眼 | 有 `selfcheck.py`/`test_*.py` 断言快照状态 ✅ | ✅ | 缺确定性/遮挡契约/越界守卫等针对性用例 |
| 8 | 单位统一 / 序列化 / 回放 / 边界 | 米+秒一致；有回放 deque ✅ | ⚠️ | `STEP_SECONDS` 未声明为常量；越界守卫缺失 |

> 一句话：**框架的"状态优先 + 服务端核心 + 快照回放 + 命令式交互"都已存在**；真正要补的是**固定步长时钟、SceneManager 独立化、确定性往返测试、越界/NaN 守卫、统一 WorldState、把上帝类拆开**。

## 2. 目标分层架构

```
┌─────────────────────────────────────────────────────────┐
│  Layer 5  UI / 交互层  (console/server.py REST+WS)        │
│   命令: insertTask / setPriority / killNest / pauseOrders │
│   → 调 core.apply_command(world, cmd) 改状态，绝不改像素   │
└───────────────────────────┬─────────────────────────────┘
                            │ 只读快照 / 下发命令
┌───────────────────────────┴─────────────────────────────┐
│  Layer 4  渲染层（只读，双实现）                           │
│   · console/static/index.html   (Web three.js)            │
│   · frontend/map_drawer_3d.py    (桌面 pygame)            │
│   契约: from_snapshot(snap) 建绘制表; 遮挡=视图层,         │
│         绝不删实体; 不回写状态                            │
└───────────────────────────┬─────────────────────────────┘
                            │ 只读 WorldState
┌───────────────────────────┴─────────────────────────────┐
│  Layer 3  仿真时钟 / 驱动器  (sim_core/clock.py)  ← 新增   │
│   FixedStepClock: 固定 dt 累加器; 服务端按 playback        │
│   速率推进; 客户端在两次快照间插值(60fps 不卡物理)         │
└───────────────────────────┬─────────────────────────────┘
                            │ advance(world, actions, dt)
┌───────────────────────────┴─────────────────────────────┐
│  Layer 2  SceneManager / 世界状态  (sim_core/scene.py) ←  │
│   WorldState(全部实体+时钟+随机态+指标)                    │
│   registry CRUD / serialize / checkpoint / restore /      │
│   step_history(deque)  ← 把 sim_session 散落的 *_snapshot │
│   收敛到这一层                                           │
└───────────────────────────┬─────────────────────────────┘
                            │ 纯逻辑
┌───────────────────────────┴─────────────────────────────┐
│  Layer 1  Simulation Core  (sim_core/core.py 等) 纯逻辑   │
│   · kinematics 航线跟随 / 能耗 / 任务生命周期             │
│   · demand     需求生成(热点+潮汐, 已现实锚定)            │
│   · arbitration 机巢泊位仲裁                             │
│   · routing    规划期绕建筑/禁飞                          │
│   · collision  运动学避障(显式决策: 不引物理引擎)         │
│   · rng        集中式可种子随机源(可快照)  ← 新增         │
│   不 import 任何渲染库 / 不碰网络                         │
└─────────────────────────────────────────────────────────┘
Layer 0  领域实体  (sim_core/entities.py)
         DroneState / TaskState / NestState / NoFlyZoneState
         @dataclass: 物理属性(位置/速度/电量/载重) +
         业务属性(id/标签); 渲染属性(颜色/visible)不在此层
```

### 与"不动目录"约束的兼容
新增 `sim_core/` 包（**纯增不搬**）；把 `Environment` 重构成 `SimulationCore` 的**薄编排器**（保留类名与公开方法，内部委托给 `sim_core`），`sim_session` 的 API 与 `release_check`/`selfcheck`/文档引用**全部不动**。

## 3. 各层落地要点

### 3.1 领域实体（`sim_core/entities.py`）
把现有 `drone.py/task.py/nest.py/no_fly_zone.py` 的"物理+业务"属性抽成 `@dataclass`，统一 `to_dict()/from_dict()`。
- 物理属性：`pos(x,y)`、`battery`、`load`、`status`
- 业务属性：`id`、`category`、`priority`、`deadline`
- **渲染属性（颜色/visible）不入实体**，由渲染适配层另行维护（落实 2.2）。

### 3.2 Simulation Core（`sim_core/core.py`）
`advance(world, actions, dt) -> None`（原地确定性推进）：
1. 应用本步 actions（分配航线 / 任务链 / 顺路接入）。
2. `world.clock += dt`；按需 `demand.step()` 生成新任务。
3. 每架 `drone.update(dt)`：沿航点运动、扣电、到点点取/送、低电改道换电。
4. **越界/NaN 守卫**（补 1.3/8.4）：位置超出 `global_bounds` → clamp 并置 `drone.flag_out_of_bounds`；`math.isnan` → 回滚到上一合法位置并标记。
5. 统计：里程(空载/载货)、能耗、利用率、完成/超时。
6. 返回 observation/reward/done（供 MARL 与基线）。

**硬约束**：本文件及 `sim_core/` 下**禁止 import pygame / three / fastapi**；用 `python -c "import sim_core.core"` 可无头跑通即达标。

### 3.3 SceneManager（`sim_core/scene.py`）—— 补 Layer 2
把 `sim_session` 里散落的 `_drones_snapshot/_nests_snapshot/_tasks_snapshot/...` 收敛为：
- `WorldState` 单一容器 + `SceneManager.registry`（按 id 增删查）
- `serialize()/deserialize()`：整世界状态 ↔ dict（即现有 snapshot 内容）
- `checkpoint()/restore()` + `step_history`（deque，回放拖拽）
- `hash_state()`：供确定性测试比对

### 3.4 仿真时钟（`sim_core/clock.py`）—— 补 1.2
`FixedStepClock(acc, dt=STEP_SECONDS)`：服务端后台任务按 playback 速率（如 1×=1 步/秒）推进核心；客户端拿到相邻两次快照做**线性插值**得到 60fps 平滑画面，物理速率与渲染帧率彻底解耦。即使画面卡，物理也不变慢、结果不变。

### 3.5 渲染层契约（落实 2.2 / 3）
渲染适配层新增显式不变量：
- `RenderAdapter.build(scene_manager)`：从 WorldState 建绘制表；
- `occlusion` 是**视图层标记**（`entity.render.visible=False`），实体仍在 `WorldState`；
- **严禁**因不可见而从 SceneManager 删除实体；
- 加 `tests/test_occlusion_contract.py`：断言"被遮挡实体的 `WorldState` 位置不变、未被移除"。

### 3.6 交互层（已对，落成硬契约）
`server.py` 命令 → `core.apply_command(world, cmd)`；任何命令失败必须**整体回滚**，世界状态不变（对应 selfcheck 的"检查点后状态异常"断言）。

## 4. 物理引擎选型决策（框架 §6）

**结论：不引入 PyBullet / Bullet3 / ODE。**
- 本项目是**运动学调度-优化仿真**，不是刚体动力学仿真：无人机沿**预规划航线**匀速运动，楼宇/禁飞在**规划期**用 A* 绕开，不存在实时碰撞冲量、摩擦、弹性需求。
- 引入物理引擎只会增加依赖与不确定性（多线程破坏确定性，见 4 条），却建模不了真实问题。
- 例外：若未来要加"风场扰动漂移""真实悬停-巡航能耗差"（世界逻辑规格书缺口 B），仍可在 `core` 内用**确定性解析公式**实现，不必上引擎。
- 记录为 deliberate decision，写进本文件与 README。

---

## 5. 确定性审计（框架 §4 / §7）

1. **随机源集中**：所有 `random`/`numpy` 调用走 `sim_core/rng.py` 的单一 `Random`/`Generator`，其状态随 `WorldState` 序列化 → 快照往返可复现。
2. **单线程**：核心严格单线程（现状已是）。
3. **测试**：
   - `test_determinism.py`：同 seed → 两次 run 的 `hash_state()` 序列逐拍相等；以及 `save→load→step` 与连续 run 逐拍相等。
   - `test_core_state.py`：暂停自动订单流 → 既有任务位置不变；非法命令被拒 → 世界不变；无人机越界 → clamp+flag，无 NaN。
   - `test_occlusion_contract.py`：遮挡不改 WorldState、不删实体。
4. 这些测试**完全不启动渲染**（import `sim_core` 即可），落实"肉眼只做最后验证"。

---

## 6. 单位与边界（框架 §8）

- 新增 `sim_core/units.py`：`STEP_SECONDS = 1.0`（1 步=1 秒，episode=3600 步=1 小时，与世界逻辑规格书对齐）；全系统米 / 秒 / kg / Wh 统一。
- 边界守卫（3.2 第 4 步）+ 数值爆炸兜底（drone 卡死检测：连续 N 步未移动且无任务 → 标记 + 日志，不静默）。

## 7. 迁移路线（与改造方案 P0/P1/P2 对齐）

| 阶段 | 动作 | 对应框架缺口 | 不破坏 |
|---|---|---|---|
| P0a | 新增 `sim_core/` 包 + `entities/world/scene/core/clock/rng/units` 骨架；`Environment` 改为委托薄壳 | 5 / 2.1 / 1.2 / 4 | `sim_session` API、文档引用 |
| P0b | `SimSession` 的 `*_snapshot` 收敛进 `SceneManager`；加 `hash_state` | 2 / 4 | 外部快照字段不变 |
| P1 | `server` 加 `FixedStepClock` 后台推进；Web 客户端插值渲染 | 1.2 | REST 接口兼容 |
| P1b | 渲染适配层加 `visible` 渲染标记 + 遮挡不变量 + 契约测试 | 2.2 / 3 | 视觉无回归 |
| P2 | 越界/NaN 守卫、风场(可选)、三维地形避让；"仿真设定/数据来源"面板亮出真实性 | 1.3 / B / C / E | 世界逻辑规格书 |

> 优先级：**1.2 固定步长时钟** 与 **SceneManager 独立化** 是地基，先做；渲染解耦与"真实性呈现"紧随（直接消除用户说的"假"）。

---

## 8. 一句话交付判定

现有项目**不是"AI 视频式假仿真"**——它已经有服务端无头核心 + 状态快照 + 快照回放 + 命令式交互，符合框架内核。真正要补的是把"碰巧对"变成"设计保证"：**独立 SceneManager、固定步长时钟、确定性往返测试、越界/NaN 守卫、显式渲染不变量、把 91KB 上帝类拆成可单测的 `sim_core`**。物理引擎明确不用。
