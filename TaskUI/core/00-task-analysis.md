# Core 00 — 任务与对象建模

## 输入

目标用户、使用环境、典型任务、关键对象与对象状态。不能确定时先写假设，避免用“可能需要一个炫酷数据大屏”替代需求分析。

## 任务表（每个主要任务一行）

| 字段 | 说明 |
| --- | --- |
| 任务 ID / 名称 | 动词 + 对象，例：筛选图片、编辑文章、定位异常 |
| 触发场景 | 从哪个状态开始，是否已选中对象 |
| 频率 | high / medium / low（基于用户证据；缺证据写假设） |
| 风险 | low / medium / high |
| 完成标准 | 用户可观察的明确结果 |
| 操作序列 | 用户真实执行的动作，而非页面名称 |
| 步数预算 | 按 manifest 抽象操作粒度自行设定并解释；不等于实际点击次数或耗时，不套用统一阈值 |
| 出错恢复 | 撤销、重试、版本恢复、取消等 |

## 对象模型

区分业务对象（文件、订单、任务、无人机）、对象集合、对象属性、对象生命周期和对象级操作。将创建/查看/编辑/删除/过滤等附着于相关对象，不要先按功能名称拆分页面。

## G0 退出标准

至少识别 3 个真实核心任务；小工具不足 3 个时可说明理由。各任务均有可观察完成条件和起始状态。缺乏可靠频率数据须说明是假设；不因“高频”这个标签自动推导必须常驻按钮。
