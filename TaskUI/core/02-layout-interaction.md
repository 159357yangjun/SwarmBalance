# Core 02 — 工作区布局与交互行为

## 空间分配

先选主工作区，再定导航、属性、预览、日志、筛选等辅助区域。辅助区域必须能说明“何时被看见、为何常驻、可否收起”。布局保持稳定，不因每个功能都新增侧栏。

**比例不是硬性美学指标**：`main_region_min_ratio` 是在清单中声明的设计意图，并不等于实际 UI 已实现该比例。检查脚本仅能检查数值有效性；实际测量依赖目标视口截图和 DOM/窗口分析。

## 渐进式披露

- 必需信息直接出现；附加信息按需要出现。
- 首选就地操作、局部面板、上下文菜单，必要时才开全屏页面。
- 对象为空时不展示大量不可用按钮；清楚说明下一步。
- 避免“一个标签页里再套多层标签页”的迷宫式导航。

## 完整交互状态

对于所有修改类操作：定义触发条件、校验、处理中、成功、失败、取消和恢复方式。对于列表/查询：定义空结果、加载、分页/增量加载、过滤重置及焦点保留。高风险操作不等于一律弹确认框，应权衡误触成本和恢复能力。

## 无障碍与输入

桌面与 Web：优先检查键盘可达、焦点可见、Tab 顺序、菜单 Escape 行为、快捷键冲突。触摸设备：检查触摸目标尺寸和误触风险。颜色不可作为状态的唯一表达方式。

## 视觉约束

使用设计 Token（色彩语义、字号、间距、尺寸、分割、焦点、状态），但不能用无意义的卡片、阴影、渐变替代清楚的信息层级。根据任务选择密度；不以“所有页面看起来一样”牺牲专业场景的差异性。
